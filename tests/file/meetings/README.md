# 会议垂直合成测试数据（1.7）

**全部虚构 · 非真实会议。** 两套合成会议，人物、公司、产品、项目全是编的，跟任何真实个人 / 组织 / 项目无关，只用来验证 BookScope 会议垂直功能的抽取质量。

配套设计稿：`docs/design/WP-1.7-action-ledger-schema-prompt.md`（schema + 抽取 prompt）、`docs/design/WP-1.7-meeting-vertical.md`（方向稿）。

两套测试数据：

- **星图系列**（`meeting-01~04`）：同一个虚构开源项目「星图」的 4 次连续周会，体量小（一两千字），早期搭的最小验证集，主要测单会抽取的基本盘 + 形态门控。
- **云栖系列**（`meeting-05~10`）：虚构公司「云栖科技」二季度的 6 场不同类型会议，体量大（决策 / 评审 / 协调三场逐字稿都是五千到八千字的真实长度），跨越两个多月，是杀手场景的主验证集——**一条数据迁移线、一条增长线、一条技术债线跨多场会，看承诺到底兑现了、漂没了还是被推诿了**。

人物全是职能化代号：周明（CEO）、林涛（CTO）、陈悦（产品总监）、吴帆（增长负责人）、黄睿（销售负责人）、钱蕾（财务负责人）、赵宏（后端负责人）、孙婕（前端负责人）、郑磊（运维负责人）、刘洋（设计负责人）；星图系列用 PM-A / Eng-B / Eng-C / Eng-D 等代号。

## 二、云栖系列跨会承诺—兑现链（杀手场景验证主线）

云栖 6 场会的核心价值在这里：**同一件事跨多场会反复出现，看它到底走向哪。** 每份文件头部埋点里都标了本场是这条线的哪一站，下面把三条主线 + 两条辅线归纳成表。

| 承诺线 | 决策会 05（4/2） | 评审会 06（5/8） | 协调会 07（5/19） | 复盘会 08（6/11） | 技术纪要 09（6/23） | 简报 10（6月） | 终态 |
|---|---|---|---|---|---|---|---|
| **数据迁移**（赵宏） | 未直接派 | 正式立项「两周出方案」、已动工 | 演练通过、生产窗口待定 | 生产迁移已排 6/20 | 6/20 完成、运行稳定、结项 | 性能提升反映在客户满意度回升 | **已兑现**（曾两次滚动推迟，全程有 owner+硬节点） |
| **增长方案 / 峰会**（吴帆） | 承诺月底出完整方案（due 季度末） | 方案出了、在收预算（部分兑现） | 预算批了一部分、超的部分悬着 | 方案落地、峰会办了、增长数据出来了 | — | 峰会商机本月转化签约 3 家 | **已兑现**（落地后转化是滞后兑现） |
| **技术债治理**（林涛提，周明压） | 「原则上同意、放三季度」（开环，无 owner 无硬 due） | 追问能否提前，被「抽空整清单、三季度排」挡回 | **完全没被提起（沉默一站）** | 林涛再提，周明「今年排不上、明年初吧」 | — | 「经多次研究，已调整至明年第一季度统筹」 | **全程漂没典型** · 从「原则上支持」到「重视」到沉默到「明年再说」，四 / 五场会永远没 owner+硬 due |
| **预算复核**（钱蕾） | 周五前给预算范围 | 方案在收预算 | 被追问「集团还在走流程」（推诿） | 集团批一部分、超支那块公司垫了 | — | 差额核算口径「仍在与集团对接中」 | **拖到最后兜底**，过程一直甩给「等集团」 |
| **监控告警治理**（运维） | — | 「找时间梳理一下」（开环，owner 空 due 空） | — | — | 「持续推进、已梳理部分规则」，不设硬节点 | 「按既定计划推进中」 | **缓慢推进**，长期无硬节点的开环事项 |

**技术债这条线是最典型的漂没教学样本**：一件 CTO 一直想做、CEO 嘴上「很重要要重视」的事，跨四场会从「原则上支持」一路滑到「明年再说」，全程没人正式接、没硬截止日。验证时它的含金量该判「空头表态」，`loose_end` 该一直亮，绝不能因为 CEO 说了「重视」就误当成已决议或真金白银的行动项。对照之下数据迁移线（有具体 owner、每场都推进、最后真上线）是「真金白银」正例——两条线放一起，正好测含金量判断分得开。

## 三、单会埋点矩阵（每份会内验证什么）

每份文件顶部都有自己的埋点说明块（写明本场的闭环 / 开环行动项、议而未决、立场张力、弦外、反复短发言具体是哪几处），这里只给总览，细节看各文件头部。

| 埋点类型 | 主要在哪几份 | 验证什么 |
|---|---|---|
| 闭环行动项（owner + due 全） | 全部逐字稿 + 09 / 10 | 行动项抽取 + substance 判「真金白银」 |
| 开环行动项（owner 缺 / due 缺） | 05（技术债「下季度排一排」、赠品「找人弄一下」）、06（监控「找时间梳理」、技术债清单）、07（现场答疑 / 会后复盘 / 通稿都含糊到「找人 / 市场」）、08（流失分析「找人看一下」、技术债「到时候再说」） | owner / due 留空、`loose_end=true`、含金量判「空头表态」 |
| 议而未决（不能脑补成决议） | 05（定价调整「先放放」、自建 IM「再调研」）、06（组件库推倒重做「拿不准」、灰度系统「再看看」）、07（峰会超支谁出「先垫着事后再说」、嘉宾顺序「再排排」）、08（峰会问责「不追个人责」、三季度招人「等预算」）、09（消息队列「暂不决策」）、10（海外市场「列入下月专题」） | 不被误当 decision 混进 decisions |
| 立场张力（逐字稿里读语气） | 05 / 06 / 07 / 08（如林涛挺技术债被压、钱蕾对预算回避、黄睿对砍小客户软反对、陈悦对发版本时间反对、黄睿对峰会转化泼冷水） | 立场 / 软反对能被识别，但首炮不强抽，给后续「立场弦外」备料 |
| 弦外（表面 A 实则 B） | 05 / 06 / 07 / 08（如「这个得看集团意思」=甩锅、「原则上肯定支持但排期满」=拖延、「发是可以发但出问题别怪我」=甩责、「我尽量但不敢保证」=留口子） | 给立场弦外功能备料；首炮验证它不被误当 decision；**纪要 09 / 简报 10 里读不出语气，弦外必须优雅退场，不许硬编** |
| 同一人反复短发言 | 全部逐字稿（周明「嗯 / 行 / 好 / 对对对」、吴帆「对 / 没错」、钱蕾「这个……」） | 关键 decision / action 的 evidence 要摘足够长上下文，**不锚到泛滥的「同意」短句** |
| 纪要 / 简报无主语、到组级 owner | 09（「由后端组负责」「会议决定」「相关人员配合」）、10（「客户成功组牵头、销售组配合」） | owner 到「组」级 / 「会议决定」不算抽坏，区别于逐字稿里该有具体人却空了的真信号 |
| 通报不被脑补成决议 | 10（简报大部分条目是进展 / 数据通报，只有「成立大客户验收专项小组」一条是真决议） | 通报式条目议程项状态多为「仅通报」，不该被硬塞 owner 当 `loose_end` |
| N/A 区分 | 09 / 10（无缺席 / 列席逐字痕迹、无具体发言名单） | 相关 head 字段可留空 / 标 N/A，不算抽坏 |
| 长期未决最终拍板 | 星图 04（v2.0 定 4/15）、云栖 08 → 10（技术债「定」到明年初） | 前几次「再议」的事后来真拍了 → 该进 decisions；注意技术债的「定明年初」是搁置式拍板，含金量仍低 |

## 四、用法（给 BE / QA）

- 这些是 `.txt` 纯文本，走现有 ingest 当一份「文档」喂进会脉构建（结论项 prompt 抽 decisions + action_items）。
- 抽取正确性判据见设计稿 §4「为什么这样设计能跑通」+ §5「合成测试数据怎么覆盖跨会追承诺」。
- 跨会追踪（杀手场景）用云栖 05~10 这条线验证：拿数据迁移 / 增长 / 技术债三条线问「这件事最后兑现没」，对照第二节的终态列判对错。
- 验证纪律照 `feedback_probe_avoid_general_knowledge`：**别用「这会谁参加了」这种一眼可见的题验证，验证题落在判断层**——「本场真拍板的决议有几条」「哪些行动项没人接（owner 空）」「技术债治理跨四场会到底兑现了没」「这份纪要里有没有该判 N/A 的字段」。
- 跨题材回归（会议门控不误伤书 / 公文）留到接 `genre_detect` 那一步，首炮抽取层不涉及。
