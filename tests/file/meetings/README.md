## 跨会承诺—兑现链（杀手场景的验证主线）

首炮**不做**跨会视图，但测试数据把跨会关系埋进去，目的有二：① 给第二步（跨会承诺-兑现追踪）备好验证集；② 验证**单会抽取在「同一 owner 的同一件事跨会反复出现」时不串台、不锚错轮**。

四条承诺线，跨会状态演变：

| 承诺 | 第1次会 | 第2次会 | 第3次会 | 第4次会 | 终态 |
|---|---|---|---|---|---|
| Eng-B 鉴权接口 | 承诺「下周一出初版」 | 部分完成、改期到「周三」 | 已完成并合入 | （结项维护） | **已兑现（曾滚动推迟）** |
| Eng-C 文档站 | 承诺「周五上线」 | 已上线 | — | — | **已兑现** |
| Eng-D 性能优化 | 「回头安排人」（开环） | 定 owner=Eng-D、due=3月24 | 进行中、按期 | 已交付验收 | **已兑现** |
| Eng-C 社区运营 | 「大家上点心」（无 owner） | 仍无 owner | 定 owner=Eng-C、无硬节点 | 贡献指南没动、只回了 issue | **未兑现（开环漂没典型）** |

这条「社区运营」线是教学样本：一件事从「没人接」到「定了 owner 但没硬节点」到「还是没做」，正是开环行动项漂没的全过程，含金量该判「空头表态/有条件兑现」、`loose_end` 该亮。

## 单会埋点矩阵（每份会内验证什么）

| 埋点类型 | 在哪份 | 验证什么 |
|---|---|---|
| 带 owner+due 的闭环行动项 | 全部 | 行动项抽取 + substance 判「真金白银」 |
| owner 缺失的开环行动项 | 1（性能「回头安排人」）、4（周边物料「找人弄」） | owner 留空、`loose_end=true`、含金量「空头表态」 |
| due 缺失的开环行动项 | 1（社区「尽快搞」）、2（logo「有空弄」）、4（example「抽空建」） | due 留空、`loose_end=true` |
| 议而未决（不能脑补成决议） | 1（换日志库「再议」、v2.0「下次定」）、2（v2.0「再放放」）、3（日志库「暂缓」） | 不被误当 decision 混进 decisions；首炮 open_issues 恒空 |
| 长期未决最终拍板 | 4（v2.0 定 4月15） | 前三次「再议」的事，第4次真拍板了 → 该进 decisions |
| 同一人反复短发言 | 全部（PM-A「好/行/可以」、Eng-B「嗯/对/行」） | evidence 摘长 + 锚错防护：关键 decision/action 的 evidence 带足够长上下文，不锚到泛滥的「同意」 |
| 纪要无主语/到组级 owner | 3（「前端组负责」「会议决定」） | owner 到「组」级不算抽坏；区别于逐字稿里该有具体人却空了的真信号 |
| 软反对 / 分歧（首炮不抽） | 4（Eng-B 对 4月15「太赶」反复保留，PM-A 拍板） | 给第四炮「立场弦外」备料；首炮验证它不被误当 decision |

## 用法（给 BE / QA）

- 这些是 `.txt` 纯文本，走现有 ingest 当一份「文档」喂进会脉构建（结论项 prompt 抽 decisions + action_items）。
- 抽取正确性判据见设计稿 §4「为什么这样设计能跑通」+ §5「合成测试数据怎么覆盖跨会追承诺」。
- 验证纪律照 `feedback_probe_avoid_general_knowledge`：别用「这会谁参加了」这种一眼可见的题验证，验证题落在判断层——「本场真拍板的决议有几条」「哪些行动项没人接（owner 空）」「Eng-C 社区运营兑现没」。
- 跨题材回归（会议门控不误伤书/公文）留到接 `genre_detect` 那一步，首炮抽取层不涉及。
