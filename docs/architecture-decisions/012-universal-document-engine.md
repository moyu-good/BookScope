# ADR-012:通用深度文档分析引擎扩张(从书籍深读到任意长文档)

**状态**:待作者签字(草稿 · Claude 起草 · 2026-06-29)
**关联**:`docs/internal/NORTH_STAR.md`(已广义化)、ADR-010(章脉共享索引,引擎地基)、`docs/design/WP-1.6-redhead-vertical-design.md`(公文)、`docs/design/WP-1.7-meeting-vertical.md`(会议)、`.claude/skills/vertical-design`(七步方法论)

> 追认性 ADR:这个方向决定 2026-06-24 作者已拍板、NORTH_STAR 已改、公文(1.6)+ 会议(1.7)已建。当时只改 NORTH_STAR + 直接开建,没立 ADR。2026-06-29 文档审计发现缺这份代际级记录,补立。

## 背景

BookScope 起家是"书籍深度分析"。2026-06-24 作者拍板:扩成"通用深度文档分析引擎、使用场景全包"——书只是第一类,不是唯一。理由:章脉那套"整本读一次出带证据的结构化骨架、十几个功能从它派生"的引擎,不挑题材;长公文、会议记录这些"想读懂却难自助"的长文档,同样吃这套。

这动了立身定位(NORTH_STAR 里"书籍"那条),是代际级方向变动,该有一份 ADR。当时漏了,本份补。注意:这是**定位 / 场景的代际**,不是架构代际——runtime 仍是 r2 协议、引擎仍是章脉,没换地基。

## 决定

1. **定位广义化**:BookScope 从"书籍深度分析系统"扩成"任意长文档深度分析引擎"。书籍是第一类、是出发点,不是唯一服务对象。
2. **一台引擎接多垂直**:章脉 → 文脉 → 会脉是同一套引擎、不同承载单元——一次带证据的结构化通读,十几个功能从它派生(纯计算或轻 LLM)。分析单元随题材自适应(书的章 / 公文的条款 / 会议的议程项 · 发言轮)。
3. **已落地垂直**:书籍(基线)、**公文**(1.6.0 发版,党政红头文件,有 GB/T 9704 公文格式标准当 ground truth)、**会议**(1.7 已建未推,行动项台账 + 悬而未决 + 跨会议追承诺)。
4. **杀手价值在跨文件 / 跨单元**:公文的依据链网 / 上下级、会议的跨会承诺—兑现——单份分析谁都能做,跨单元追踪才是这引擎不可替代的地方。
5. **底线跨垂直全守、不因扩张松动**:evidence-first(没原文证据不输出)、核过盖「鉴」/ 推断标「研判」、BYOK(用户自带 key、不入库)、CPU-only(禁 GPU)、国内 LLM 优先、产出无真名。新垂直一个不豁免。
6. **新垂直走七步方法论 + design-first**:定单元 → 建证据脊 → 选角度 → 派生视图 → 证据为根 → 题材自适应退场 → 视图协同(固化成 `vertical-design` skill)。先小样本证根、再铺开。

## 后果

- **加分**:复用章脉 / cross_doc 底座,新垂直边际成本低(会议三炮大量复用公文跨文件引擎,只换单元 + 关系类型)。
- **要跟上的**:① 题材门控 `genre_detect` 得随垂直扩(会议词当前还没进封闭集,会议功能暂走手动入口);② 文档 / 设计书要边开发边同步——这次审计暴露 ROADMAP / 设计书 / case-study 跟代码脱节,根因就是扩张快、文档没跟,引以为戒;③ 跨单元推理(第三档,如跨会承诺)目前每个垂直都得现啃,谈不上方法论(见 case-study 第十三章诚实记录)。
- **不变**:架构仍 r2 + 章脉,不是新架构代际;NORTH_STAR 的两形态数据底线(ADR-011)、案例研究第一交付物都不动。
