# ADR-011：托管版账号后台 + 用户数据存储（1.6.2）

**状态**：作者签字同意 · moyu-good · 2026-06-29
**关联**：`docs/design/WP-1.6.2-account-backend.md`（完整设计）

## 背景

公网托管版（Docker + Cloudflare Tunnel → 腾讯云，WS2 上线）的硬伤是一次性体验：没账号，换设备或过段时间回来要重传书、丢历史。要解决就得加账号 + 在后端留住用户的文档。这跟"本地 BYOK 工具、不碰用户数据"的原始形态冲突，是代际级决定，故立 ADR。

## 决定

1. **两形态共存、不分叉代码**：一个开关 `BOOKSCOPE_DEPLOYMENT_MODE = local | hosted`（默认 local，复用现有 env-mode 套路）。
   - **本地克隆版**：账号层旁路，行为跟今天逐字节一致、零回归；DB / 邮件 / 短信根本不加载。
   - **托管版**：挂账号 + DB + 每个 session 带 `owner_id` + 按用户分目录存。复用现有 `SessionStorage`（托管版本来就落盘），只加一层归属 + 一道鉴权闸，现有端点签名几乎不动。
2. **托管版存用户文档**（书 / 公文 + 派生索引 + 缓存）：加密盘 + 账号隔离 + 用户可彻底删除（连索引缓存一起删）。
3. **API key 永不入库**：两形态都只让 key 留浏览器、按请求传、用完即弃，任何表都没有 key 字段。
4. **版本号 = 1.6.2**（旧 1.6.1 = 利害与风向已随 1.6.0 发版，不占号）。
5. **MVP = Phase 1「账号 + 文档归属」**先行（命门是归属层别污染本地版 + 数据隔离对不对）；邮件 / 短信验证、找回密码、隐私政策 / 删除权收尾分 Phase 2-3。Phase 0 必过"本地版全套测试零回归"闸。

## 对底线的让步（作者已同意）

NORTH_STAR / README 原说"碰不到你的书，也碰不到你的 key"。本决定让步**只有"碰不到你的书"半条，且只在用户主动选托管版时**：托管版存你的文档（加密 + 隔离 + 可删）。

**不让步的**：碰不到你的 key（key 焊死客户端）、evidence-first、BYOK、CPU-only、国内优先、无真名——两形态全守。本地克隆版仍守全部底线、无服务器。

## 后果

- 加责任：存用户文档 + 邮箱 / 手机（PII）→《个保法》个人信息处理者，要管加密存储、访问控制、泄露风险、留存 / 删除权、隐私政策。这是本决定最大的成本，不是服务器配置。
- 加依赖：持久盘、数据库（先 SQLite 后 Postgres）、邮件服务、短信服务。
- 算力不变：仍 CPU、不要 GPU（分析是 BYOK，推理在用户的 key / 厂商那边）。
- 本地版不受影响。
