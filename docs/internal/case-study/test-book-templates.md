# BookScope 测试书模板

**这份文档是干什么的**：BookScope 开发期间真在用的几本测试书的全档案——身份、来源、合法性、覆盖什么测试场景、跑过哪些 batch 实验、对应数据散在哪里。读者（包括副管理未来 session 失忆后）看完这一份，应该不需要再翻 STATE 历史就能知道当前测试基底长什么样。

写下来的另一个理由是：开发期不绑作者私稿。作者本人写网文，几十万到几百万字的草稿在外面摆着，BookScope 的终极使用场景里它一定出现——但开发过程不靠它。作者不交物料、AI 不催物料、副管理也不在 STATE 头注里写"等作者放小说稿"这种被动等命。当前四本 epub 就是开发期完整的真测试资产，本文档把它们正式登记。

**2026-05-18 第十六波扩档**：原来只有 mingchao 加 anshi 两本。Sprint 3 启动那天作者亲选了两本——制内市场（郑永年政经论说）加亏成首富（青衫取醉网文）——直接入仓，作废之前 RE 自决出的"老残游记 + 论语"候选方案（见第八节）。新两本下面占第三、四节。

## 一 mingchao —— 公开热门 baseline

**真实身份**：当年明月，《明朝那些事儿》。中文互联网上 2006 年起连载、后整理成七卷出版的通俗历史叙事文。讲明朝从朱元璋起兵到崇祯亡国的完整朝代史，语言口语化、调侃式，影响了一整代网络历史写作。

**仓库路径**：`C:\project file\BookScope\test明朝那些事儿.epub`。

**实际用了哪一卷**：七卷里取卷一（朱元璋起兵到永乐迁都段）作为测试切片。`v2-batch-01.json` 元数据写明 `word_count: 32164` / `chunk_count: 1069`——一本完整七卷书的总字数远超这个数，所以现在跑的不是整套。这个切片选择从 v2 一直延续到 sprint5 r1/r2 对照，跨度从 4 月底到 5 月中。

**合法性**：当年明月七卷本由公开出版社出版，公网有正版电子版渠道，epub 在 BookScope 仓库内仅作开发期测试用途，不分发、不嵌入 release artifact、不上传到任何 OSS 镜像。仓库的 `.gitignore` 暂未把 epub 列入排除——后续如果项目对外发布要把 epub 移到本地 data 目录而不放进 git 历史，这是一个待办。

**覆盖什么测试场景**：

- 通识题——比如"朱元璋的小名是什么"、"鄱阳湖大战对手是谁"、"全书语言风格的标志性特点"。这类题维基级常识可以答出来，**不适合用来证明 BookScope 真读了原文**，但适合做 smoke test 看 agent 是否能跑通工具调用链路
- 历史评论题——比如"朱元璋这个人物的塑造算成功吗"，需要 agent 拉原文章节论证
- 铺垫连贯性——"清洗开国功臣的弧线节奏是否匀速"、"贫农出身这条伏笔是否在后期得到回收"——这类题已经接近作家诊断题的形态

**训练污染状态**：第 33 轮 `exp003-training-contamination-probe` 揭出 MiniMax-M2.7 在 mingchao 通识题上几乎全对——朱重八、1344 年开篇、鄱阳湖打陈友谅、李善长被胡惟庸案牵连、当年明月的语言风格——全部凭训练记忆答出。**这意味着 mingchao baseline 分数天然虚高**，agent 即使没真去查原文也能蒙到分。第 33 轮第三部分跑 v3.3 prompt 把 mingchao 分数从虚高位拉回 19.5 诚实段位就是冲着这个污染打的。

**关键 batch 数据**（按时间序）：

- `v2-batch-01.json`（2026-04-24，loop_system_prompt_v2 + astron）
- `v3-minimax-batch-pilot-no-enforcement.json` / `v3-minimax-pilot-2.json`（v3 早期 pilot）
- `v3.1-minimax-pilot.json` / `v3.1-minimax-batch-01.json`
- `v3.2-minimax-batch-01.json` / `v3.2-mingchao-minimax-batch-02.json` / `v3.2-mingchao-minimax-batch-03.json`（第 33 轮第五部分发现 v3.2 baseline 3 次 std = 1.06，单跑不能当 ground truth）
- `v3.3-mingchao-minimax-batch-01.json`（第 33 轮第三部分诚实段位收敛）
- `v3.4-mingchao-minimax-batch-01.json`
- `exp003-minimax-v2-ablation.json`（v2 在 minimax 上的 ablation）
- `sprint5-mingchao-r1-batch-01/02/03.json` + `sprint5-mingchao-r2-batch-01/02/03.json`（Sprint 5 r1 vs r2 协议对照各 3 次）

## 二 anshi —— 冷门学者非虚构 baseline

**真实身份**：张诗坪、胡可奇，《安史之乱：历史、宣传与神话》。学者向非虚构作品，2024 年后出版。副标题摆出了书的核心立场——传统叙事里混入了大量战时宣传与后世改写，作者要把它剥离出来。这本书在公开网络上有 KOL 推荐过，但远不如《明朝那些事儿》家喻户晓。

**仓库路径**：`C:\project file\BookScope\test安史之乱  历史、宣传与神话 (张诗坪, 胡可奇).epub`。文件名中间有两个空格——shell 里要整体引号否则会被切。

**整本规模**：`exp002-anshi-questions.json` 元数据写明 `char_count: 394761` / `chunks: 267` / `chapters: 29`。和 mingchao 卷一切片相比，anshi 是整本，字数多十倍，chunk 数却只有四分之一——这是因为两本书的 chunker 参数不一样（mingchao 用较细的切分，anshi 用较粗的）。这条不一致进了文末工程债清单。

**合法性**：2024 年出版的学者作品，正版渠道可购。epub 同样仅作开发期内部测试用途，不分发。版权敏感度比 mingchao 更高——anshi 出版年份新、商业潜力还在，如果项目走向对外发布要么换公版历史著作，要么把 epub 路径从仓库迁出去只留 schema 与数据。

**覆盖什么测试场景**：

- 作家诊断题——节奏 / 支线密度 / 论点铺垫与回扣 / 历史人物形象建构 / 作者立场一致性，5 道题完整覆盖
- 训练污染对照——anshi 出版晚于一部分模型训练截止 + 远没有 mingchao 热门，**LLM 没读过原文的概率高**。这是 anshi 真正的测试价值——它是 BookScope agent loop "走原文证据"机制的真烧炉

**训练污染状态**：第 33 轮 probe 在 anshi 上拿到了硬证据——MiniMax-M2.7 在被问及"睢阳保卫战的鬼故事化处理"时编出了一个根本不存在的作者"Benjamin T. Tully（郭瑞德）"，在被问及"全书章节数与编排顺序"时编出了一个学术论文集编辑者"Mark Edward Lewis"。这两个名字都不是本书真作者，是模型在训练里见过的、跟唐史相关的西方汉学家姓名被误粘到了这本书上。**这条编造行为本身就是 BookScope 该解决的问题**——没读过原文就不准回答，要靠原文证据兜底，不靠训练记忆。

**关键 batch 数据**（按时间序）：

- `exp002-anshi-questions.json`（2026-04-30 题目集定义）
- `exp002-anshi-minimax-v3.2.json` + `exp002-anshi-minimax-v3.2-rerun-01/02-with-retry/03/04.json`（v3.2 跑了 5 次求方差）
- `exp002-anshi-q1-only-maxiter12.json`（q1 单题加 maxiter 实验）
- `exp002-anshi-minimax-v3.3-batch-01/02/03.json`（v3.3 跑 3 次 · 第 33 轮第三部分 q5 std 从 3.8 拉到 0.47 的数据）
- `exp002-anshi-minimax-v3.4-batch-01.json`
- `sprint5-anshi-r1-batch-01/02/03.json` + `sprint5-anshi-r2-batch-01/02/03.json`（Sprint 5 r1 vs r2 各 3 次）
- `sprint5-sanity-anshi-r1-q1.json` / `sprint5-sanity2-q1.json`（sprint 5 期间的 sanity check）

## 三 zhinei —— 政经学者论说

**真实身份**：郑永年、黄彦杰、邱道隆，《制内市场：中国国家主导型政治经济学》。郑永年是中国问题专家、高层智库学者，本书提出"制内市场（market in state）"概念解释中国政经体制——既不是西式"场内国家"，也不是简单的"国家资本主义"，而是国家原则主导市场原则的独特模式。

**仓库路径**：`C:\project file\BookScope\test制内市场.epub`（不进 git，`.gitignore` 第 45 行 `test*.epub` pattern 已拦）。

**整本规模**：`exp006-zhinei-q1-result.json` 元数据写明 `word_count: 15441` / `chunk_count: 398`。KG 提取出 67 个角色（含历史人物、当代政商人物、学者）。

**入仓时间**：2026-05-18 第十六波，作者亲选签字。同日 KG 在 minimax 上首次抽取触发 ContentFiltered 全挂——commit `0b0c2a9` 批跑降级 + `362f0ab` 重试加中性化提示把数据救回来，是通用兜底链 5 层（chapter-09 第十节）落地的直接 trigger。

**合法性**：商业出版物，正版渠道可购。epub 仅作开发期内部测试用途，不分发、不进 git。版权敏感度同 anshi——对外发布前要么换公版，要么 schema + 数据保留 / epub 路径迁出。

**覆盖什么测试场景**：

- 政经论说体——核心论点 / 案例支撑 / 历史脉络梳理 / 当代案例引用。q1 已跑通：105 秒拿到完整答复 + 多章引用（章 12 / 26 / 27 / 38 / 40 等）
- 内容审查触发点——政经文本碰 LLM 内容审查的概率远高于历史小说。本书入仓那天直接把 KG 抽取的兜底缺口暴露了出来——这条价值不在题目本身，在它当 BookScope 错误处理回归测试的"难书"角色
- 长文本压力 + 高 chunk 密度——15441 字切成 398 chunks，密度比 anshi（394761 字 / 267 chunks）高得多

**关键数据**：

- `exp006-zhinei-question.json`（题目定义，q1 政经核心论点）
- `exp006-zhinei-q1-result.json`（首次跑通 · v3 prompt + minimax · 105 秒 + 引用厚）

## 五 为什么是这四本（对照设计）

四本摆在一起承担的对照面比原来两本宽了一档：

- **训练污染光谱**——mingchao 极高（公开热门通俗史）/ anshi 低（学者非虚构 + 2024 出版）/ zhinei 中（学术专著，部分概念在训练里见过但本书未必）/ kuicheng 中位偏高（热门网文，部分模型见过部分章节）
- **文体光谱**——通俗历史叙事 / 学者非虚构论说 / 政经学术论说 / 网文喜剧。四条覆盖了"叙事 vs 论说"再叠加"通俗 vs 学术"两个轴
- **NORTH_STAR 终极使用场景代表性**——前三本都是出版物，第四本（kuicheng）才是 BookScope 真正的服务对象类型。这是本次扩档最关键的对照轴——开发期测试基底里第一次有"网文"形态
- **错误处理 trigger 价值**——zhinei 入仓当天暴露了 KG 内容审查兜底缺口，直接推出五层兜底链。这本"难书"在测试基底里有独立功能：它不只是被测的对象，还是工程容错回归测试的难度上限

**重要**：四本都不是作者私稿。开发期不绑作者本人的小说草稿——这条原则没动。kuicheng 是公开网文，不是私稿。私稿是作者开发完成后用 BookScope 的终极场景，不是开发素材。

## 六 扩档之路 · RE 自决方案作废

ROADMAP Sprint 3 写了"跨题材测试基线 4-5 本书"的目标。2026-05-17 RE agent 自决出了一份候选清单（commit `05e1532`）选了老残游记 + 论语两本，理由是"训练污染光谱中位 + 公版无版权风险 + 古典语料逼出 chunker 盲点"。

第二天作者直接撤回（commit `f57122e` revert）。撤回的理由作者第十六波末明示——

- **RE 自决越界**：选哪本测试书属于方向级判断，作者拍板，不归 RE。RE 角色边界是出候选 + 题草稿等作者签字，不是替作者选
- **方向错位**：老残 + 论语走的是"中文优先 + 训练污染光谱铺四档"那套学术对照路子；作者真正想测的是"政经论说碰内容审查"+"网文是 NORTH_STAR 真用户场景"两条
- **离 NORTH_STAR 远**：作者要做的是给"长篇网文作者"用的工具，论语没法承担这个验证回路；古典文本和当代长文本创作场景的对应关系太弱

作者亲选的两本——zhinei + kuicheng——已在第三、四节登记。原候选清单文档 `sprint-3-cross-genre-prep.md` 保留作历史记录（未删除）但内容作废，**Sprint 3 正式入仓的就是 zhinei + kuicheng 这两本**。

未来如果要继续扩到 5 本以上：

- 候选必须先经作者明示，RE 不再自决
- 选书标准回到 NORTH_STAR——优先服务长文本创作者的真实使用场景
- 版权 / 训练污染光谱 / 文体覆盖这三条还是要看，但不当首要标准

## 八 测试用作家诊断题原文

两本书各 5 道，共 10 道。这些题是 BookScope 评估系统的真测试用例——不是通识题（"主要角色有哪几个"作家不会问），是判断题（铺垫够不够、节奏匀不匀、立场漂没漂、伏笔回扣够不够格）。这种题维基答不出，必须读原文。

### mingchao 5 道（来源 `v2-batch-01.json`）

**q1 · 节奏评估**：从第 14 章审问张士诚，到第 20 章李善长之死，朱元璋清洗开国功臣的整条弧线在叙事节奏上是否匀速？哪一段最密、哪一段最稀？密与稀的差异是作者有意控制还是结构性失衡？

**q2 · 支线密度**：陈友谅作为朱元璋建国前最大的对手，在书里的描写集中分布在哪几章？他的出场密度是否均匀，有没有明显的章节空档？书里对他的刻画是否立体，还是主要作为朱元璋的陪衬？

**q3 · 伏笔回收**：书中反复强调朱元璋的贫农出身和"血火中奋战而出"的经历，这是对他后来大规模清洗开国功臣时残暴手段的合格铺垫吗？这条伏笔埋在哪几章、回收在哪几章？铺垫是够厚还是偏薄？

**q4 · 角色转变可信度**：朱元璋从红巾军小兵到开国皇帝的权力登顶过程，书里的性格刻画有没有明显断层？作者是靠具体事件和选择展现这个转变，还是用"天命所归"式的叙事绕过了真正的性格演变描写？转变的可信度如何？

**q5 · 设定漂移**：朱元璋对"功臣"的态度在全书中发生了明显转变——早期对徐达、常遇春、李善长信任倚重，后期大规模清洗胡惟庸、蓝玉案。这个转变前后，作者给的人物底色是否一致？是同一个朱元璋在不同阶段的自然显现，还是在书中某一段之后角色形象发生了设定漂移？

### anshi 5 道（来源 `exp002-anshi-questions.json`）

注：anshi 是论说体非虚构，文学概念被改编成元历史层面——伏笔变成论点铺垫、角色转变变成历史人物形象建构、设定漂移变成作者立场一致性。

**q1 · 节奏评估**：从安禄山起兵到长安失守再到马嵬坡兵变这条主线，全书的叙事节奏是否匀速？哪一段最密、哪一段最稀？密与稀的差异是作者有意控制（比如详写灵宝之战、潼关之失这种关键转折点）还是结构性失衡？请基于具体章节中战役细节展开度、史料引用密度、作者议论穿插频率给出判断。

**q2 · 支线密度**：颜真卿、颜杲卿兄弟在河北地区的抵抗活动，是安史之乱中独立于长安主战场的重要支线。这条支线在书中的章节分布如何？是否有明显的章节空档？作者对这两兄弟的刻画是把他们当成主线战事的注脚，还是作为有自身命运弧线的独立人物来写？

**q3 · 论点铺垫与回扣**：全书副标题写明"历史、宣传与神话"，作者反复强调安史之乱的传统叙事中混入了大量交战双方的战时宣传以及后世改写。这条主线 thesis 在哪几章首次铺垫、哪几章被具体案例（如睢阳保卫战的"鬼故事"化、灵宝之战的"昏君佞臣作梗"解释）回扣验证？整条论证链是否闭环——还是只在序言提出、在正文里没有真正贯穿到底？

**q4 · 历史人物形象建构**：李隆基（唐玄宗）从开元盛世明君到安史之乱怠政昏君的形象转变，是史书叙事的经典套路。本书作者是用具体事件（财政紧张、府兵制崩坏、节度使权重失衡）来展开这个转变，还是默认了"盛极必衰"式的宿命叙事？转变的因果链是否可信、有支点事件还是凭印象跳跃？

**q5 · 作者立场一致性**：作者副标题立场鲜明——传统叙事中混入了宣传和神话需要被剥离。从前往后看，作者对"传统叙事是宣传产物"这一立场是否始终一致？哪些章节立场最强、哪些章节立场最弱（甚至回到了传统叙事框架）？是否存在某个章节之后立场漂移、回到了被作者自己批判的叙事范式？

## 九 维护约定

这份文档跟 case-study 章节、article 一样属于长线交付物，不一次性写完，跟着测试基底演化持续更新：

- **每加一本测试书，同步在前四节后加一节**——身份、来源、合法性、覆盖场景、训练污染状态、batch 数据登记
- **每跑一轮新 batch，登记到第七节清单**——文件名 + prompt 版本 + provider + 跑了几次。不登记的 batch 视为没跑过
- **每发现一道新作家诊断题，登记到第八节**——题目原文 + 类型 + 来源 batch 文件
- **作者签字定稿在里程碑点**——草稿持续滚动，定稿仪式在代际完成 / 对外发布 / 作品集整理时由作者亲笔润色。AI 不代写定稿

这份文档存在的根本目的：未来副管理 session 失忆后翻开它就能恢复测试基底全图，不用再去 STATE 头注里挖历史。

WP3（设计稿 `docs/internal/design/WP3-chapter-robustness.md`）给章节检测装上了质量指标 +

|---|---|---|---|---|
| 全书字符数 | 1,640,025 | 394,761 | 466,951 | 6,797,618 |
| chunks | 1,069 | 267 | 319 | 4,315 |
| 检出章节头 | 158 | 29 | 24 | 1,676 |

| 最长章字数 | 22,341 | 35,826 | 90,202 | 13,116 |
| 命中模式 | zh_chapter ×158 | zh_chapter ×29 | zh_chapter ×24 | zh_chapter ×1676 |
| 分卷标记 | 0 | 0 | 0 | 0 |
| 告警 | parse_inconsistent | （无） | parse_inconsistent | parse_inconsistent |
| ingest 耗时 | 0.7s | 0.3s | 0.3s | 2.6–8.3s |

读数（症状 ≠ 根因，以下是 probe 倒跳点诊断给出的直接证据，不是猜）：

- **anshi 是四本里唯一干净的**——29 个章节头全部解析成功且严格递增，真章号
  模式生效，citation 章号从此对得上书内编号。
- **mingchao 命中 parse_inconsistent 的根因是七部书各自从"第一章"重新编号**
  （倒跳点 #31/#53/#73/#97 全是"第二十几章 → 第一章"形态）。这正是设计稿
  里登记过的 chunks 数量级异常（第 48 行）背后的结构事实——之前只能猜，
  现在有数据。另发现两处正文短句误判（"第一回合就此结束。杨廷和先生胜。"
  被"第X回"模式吃进），是"回合"二字撞了"第X回"后缀——已知误判源，
  留给后续收紧（改正则会动 mingchao 历史 chunk 数基线，本 WP 不动）。
- **kuicheng 三个倒跳点**：两处是正文短行以"第一章…"开头被误判，一处是
  **真重复章号**（第1134章出现两次——网文连载平台常见事故）。重复章号正是
  单调性守护要拦的：混着用真章号会让两章共用一个 citation 坐标。
- **zhinei 的 24 个章节头是 8 章 ×3 次重复**（倒跳点 #8/#16 都是"第八章 →
  第一章"）——epub 内同一组章节文本出现了三遍（目录 / 正文 / 附录式重排，
  具体哪种待查），属于 epub 结构问题不是正则问题。
- 三本命中 parse_inconsistent 的书整书回退检测序号——**行为与 WP3 之前完全
  一致**（mingchao chunks=1069 与历史数据逐位吻合），真章号只在序列可信时
  启用。这是单调性守护"宁可统一序号，不混两种语义"的设计意图在真书上的
  首次验证。
- 三条告警规则（no_chapters_detected / chapters_too_coarse /
  suspicious_overdetection）在四本真书上零误报；zhinei 最长章 90,202 字逼近
  chapters_too_coarse 阈值（100,000）但未越线，阈值留调。
