## 序：验证完了，该上架了

chapter-11 那一天 BookScope 学会了收回错误结论。之后的几天，它在学另一件事：**把实验室里验过的能力，做成用户真能点的东西。**

前面整套案例研究的重心在"验证"——发明区六炮（伏笔、人物弧线、设定一致性、节奏、人物关系图、概念图）一个一个 probe 过闸，证明 agent 能做带原文证据的深读、不瞎编。但 probe GO 不等于产品。一个跑在 `scripts/probe_*.py` 里、把答案 dump 进 JSON 的能力，和一个用户能在界面上点一下就看到的功能，中间隔着一整段工程。

这一程就是走这段工程。结果是三类用户第一次都有了真功能落地：作家有诊断题入口和节奏曲线、读者有人物关系图、学习者有概念图。但更值得写进案例研究的不是"建了几个功能"，而是建设过程里反复撞上的同一堵墙——**reasoning model 上做结构化/长输出功能，不加防护必崩**——以及 dogfood 怎么在 ship 当天就把这堵墙拍到脸上。

本章是 chapter-11 那条"测量仪器先于实验"母题的续篇。那一章讲的是**输入端**：prompt 版本、评分仪器、数据版本锚——测量层坏了，结论跟着错。这一章讲**输出端**：模型吐出来的结构化产物（关系图、题目、曲线）会因为 reasoning 吃掉 token 预算而静默截断、会被缓存层 poison 住持续失败——输出层不设防，功能跟着崩。同一个家族，换了个位置。

## 一、跨题材图：一套机制，两个投影

第一个上架的是人物关系图——读者发明区的旗舰。NORTH_STAR 里写过一句承诺："人物关系图和概念关系图本是同一能力的两个题材投影。" 这一程把这句话从承诺变成了代码。

走的是标准两道闸：先 probe（exp-013），再建设（commit `9e56753`）。probe 验的是抽取可靠性——anshi 上抽出 24 个人物、22 条关系、**22/22 边全部原文核验通过**，每条边带章号。关键设计是把"关系图"理解成"一堆带证据的边"：每条边的 evidence 当一条 citation 过 `verify_citations`，命中 chunk 就用 chunk 的真章号覆盖模型自报的章号（chapter-11 没有的、这一程新补的"章号纠偏"，commit `d2cf156`——长上下文模型读完全书但自报章号会漂，这是 exp-009/010/011 三次都犯的老毛病）。

人物图建成后，概念图几乎是免费的。exp-014 验概念图时本来担心"概念比人名模糊"——人名是确定的命名实体，概念边界虚、表述多样。结果 zhinei（《制内市场》理论书）上一跑，担心没成真：**理论书把概念都显式定义了**（"制内市场""场内国家"是作者造的术语带定义），抽取反而比模糊实体更清晰。zhinei 上 11/11 边核验，"制内市场"稳居中心，连到国家/市场/三层市场/场内国家（对立）。

于是建设就是"小改"：把人物图的抽取函数加一个 `unit` 参数（`person` | `concept`），换一套 system 指令（节点是人物还是概念、关系类型是君臣父子还是定义包含因果），其余机制——JSON 解析、边粒度证据校验、章号纠偏、前端力导向图组件——完全共用（commit `2709397`）。前端加两个入口按钮，同一个 SVG 图组件渲染两种图。

这一节的方法论收获记进了 memory `project_invent_zone_probe_playbook.md`：**跨题材投影成立**——同一套长上下文抽取机制，把"分析单位"从人物换成概念就能跑。下一个题材（诗→意象）大概率同理。

## 二、citation 精度的两半：引用是真的，撑得起话吗？

BookScope 立身之本是"所有结论带原文证据"。但"带证据"其实有两层，这一程把两层都补齐了。

**第一半·来源真实性**（commit `43623a4`）：`verify_citations` 早就在查"snippet 在不在书里"，但只给一个 `verified` 二元。这一程把它细化成三态 `match_type`——`quote`（逐字命中）/ `paraphrase`（诚实转述，过阈值但非逐字）/ `none`（未核验）。exp-008 早发现程序校验分不开逐字和转述，这就是分开。前端每条引用挂一个证据强度徽标，用户一眼看出哪些是原话、哪些是 agent 的转述。

**第二半·论断支撑度**（exp-015 GO → commit `60ef17a`）：这是更难的一半。一条引用可以**是真的、却撑不起它配的论断**——比如答案说"杨贵妃导致唐玄宗怠政"，配一段只说"唐玄宗宠爱杨贵妃"的原文。原文是真的（过 `verify_citations`），但它只说宠爱、没说导致怠政。来源校验抓不到这种微妙误用，得靠 entailment 判定。

exp-015 验这个判定能不能做：手工标 10 对论断-引用（4 真支撑 + 6 错配，涵盖完全无关 / 提到不撑 / 过度声称三型），LLM-judge 判 supported/weak。结果满分——假阳性 0/4（真支撑不误伤）、召回 6/6（错配全揪），连难项都中："号称二十万"夸成"确实二十万"揪出、"互不服气"说成"配合无间"揪出。

建设时碰上一个产品判断：entailment 每条引用要多调一次 LLM，成本敏感。作者选了"只核转述"形态——逐字引用天然可信跳过，只核转述/未核验的，省一半成本。架构上做成单独端点 + 前端答完自动调（不碰流式主路，答案照常秒出、弱支撑徽标随后补）。撑不起论断的引用前端冒一个"⚠ 弱支撑"。

两半合起来，evidence-first 从"这句话有没有出处"升到"这个出处真不真、撑不撑得起"。

## 三、结构化输出的可靠性课：同一堵墙撞三次

这一程真正反复教训项目的，是 reasoning model 上做结构化/长输出功能的可靠性。同一堵墙，换着花样撞了几次，最后焊出一套固定防护。

**第一撞·关系图 502**（commit `464a8b7`）。人物图 ship 后作者一点就崩——后端日志 `character_graph parse failed` → 502。复现查实根因：`deepseek-v4-flash` 是 reasoning model，思考过程 `reasoning_content` 也算进 `max_tokens` 预算（chapter-11 之后才摸透的老坑，memory `reference_reasoning_model_token_budget.md`）。anshi 人物网密，模型每次出的边数在 18-47 之间浮动——撞上边多 + 思考重那次，正文 JSON 还没吐完就到 token 顶，截断成半截 JSON，解析必败。而 flash 输出上限就 ~8192，靠继续加 `max_tokens` 救不了。两道治：prompt 限图规模（最多约 30 条边，顺带图也不再是一团乱麻、更可读）+ 解析兜底（从截断的 JSON 里括号匹配抠出已闭合的完整边，502 变"看到大部分"）。

**第二撞·出题返空 + poison cache**（commit `3b23f7f`）。每书自动出题 ship 后 live 一测，200 但 0 题。复现发现：模型多数时候吐有效 JSON，但偶发吐解析不了的，而且——**L2 缓存把那条坏响应缓存住了**，导致同一本书持续返空。这是新的一课：缓存层会 poison。治法：关缓存（结构化输出功能不靠缓存）+ 解析失败重试一次（新调用通常就好）+ 同样给够 token。

**第三道·焊进去**（节奏曲线 commit `8e35566`）。到节奏曲线时，三道防护一开始就焊进去——够 token（4000）、关缓存、重试——不等它崩。live 一次过：anshi 30 章打分、铺垫章低、战斗章高。

三撞合成一条进了 memory `project_wholebook_feature_pattern.md`：**reasoning model 上做长输出/结构化输出功能，必焊三守卫**——够 max_tokens（防 reasoning 吃光截断）、关缓存（防坏响应 poison）、重试 + 截断抢救。这是 chapter-11"测量仪器先于实验"在输出端的镜像：那边是读数装置坏了下游结论错，这边是输出装置没设防功能直接崩。

还有一笔运维教训，单独记一下，因为它差点让"修复"白费：修了关系图 502 的代码、提交了，第一次重测**还是 502**——因为 uvicorn 的 `--reload` 根本没加载改动，而且旧后端缓存了坏响应。清干净进程树（含继承了监听 socket 的子 worker）、重起不带 reload 的后端，修复才真正生效。教训：本地验证 ship 后的修复，别信 `--reload`，杀进程树重起；改 BE 后必须 live 抽查，光单测和复现脚本不够——502 和出题返空都是 live 才暴露的。

## 四、dogfood 闭环：作者一点，问题就现形

这一程的节奏跟前面几章不一样：作者**边建边用**，反馈即时打回来。

最直接的一笔是 UX（commit `c03844c`）。人物图和概念图第一版做成两个并排的素文字按钮。作者试用后反馈："人物关系图和概念关系图的区分不明显，然后在 UI/UX 上不突出，我都以为这是个啥按钮呢。" 这是一句很有价值的话——功能再好，认不出来就等于没做。改法：入口从素按钮变成一个朱砂红顶边的"关系图谱"面板 + 两张带图标的卡片，每张标清描述（"谁和谁、什么关系"vs"核心概念怎么勾连"）和适用书型（小说/历史 vs 理论书/论文）。

更硬的一笔是前面讲的 502——也是 dogfood 抓的：作者点了关系图，崩了。如果没有 dogfood，这个 502 会一直潜伏到第一个真实用户头上。

dogfood 在这一程的作用，跟 chapter-08 那天一脉相承，但更紧：那天是集中试用列一批问题，这一程是建一个、试一个、打回一个、修一个。作家自试是作者不可替代的四件事之一，这一程它直接塑造了产品形态——醒目的图谱面板、不崩的抽取、看得懂的徽标，没一个是凭空设计出来的，都是被"我都以为这是个啥按钮呢"和一个 502 逼出来的。

## 五、productize 收官：降门槛 + 可视化

差异化能力建得差不多，最后两件是把它们做得更好用。

**每书自动出诊断题**（commit `9c12087`）。之前 surface 的是通用诊断题（"主角的转变是渐变还是硬扳"），但用户对**这本**书不知道具体问啥——哪条支线？哪个人物？这一笔让 AI 读完整本书，出书内专属题：anshi 上出的是"安禄山起兵的伏笔前几章埋够了吗""封常清从自信名将到畏战自保的弧线动机"——点名书里的具体人物和情节。成本敏感，做成按需 fetch（点按钮才出，不自动烧 token）。

**节奏曲线可视化**（commit `8e35566`）。exp-012 验过 agent 能判每章节奏松紧，这一笔把它做成逐章张力柱状图——柱越矮越松（拖沓）、越高越紧（高潮），点柱看这章依据。作家一眼扫出哪几章该删该加，比读一段文字描述直观。

两个功能加上前面的图和 citation 精度，三类用户的差异化能力第一次都有了界面入口。

## 六、方法论这一程长出来的两条

这一程除了功能，还沉了两条方法论，都进了 methodology-map 和 memory。

**构念效度——给主观无标准答案的能力验真**（exp-012 节奏 probe）。节奏"松不松"是主观连续判断，没有伏笔配对、矛盾检测那样的干净二元 ground truth。怎么验？借心理测量学的构念效度：没标准答案时换"对构念"——收敛（曲线和已知结构一致：高潮章高、铺垫章低）+ 复现（跨 run 稳定）+ 判别/命根子（不附和虚假框架）。这把前五炮"对 ground truth"的验法扩到了主观构念上，进了 methodology-map。

**整本书结构化功能的统一建设模式**（memory `project_wholebook_feature_pattern.md`）。关系图、出题、节奏曲线、citation 核验——四个功能长得不一样，但骨架同一套：单独端点 + 前端按需 fetch（不碰流式主路）+ 长上下文整本进 context 出结构化 JSON + 自写 SVG 不引重库 + 三可靠性守卫 + 必做一次 live 抽查。下一个整本书功能（时间线、主题追踪、论点结构、实体回溯）直接套。

## 七、收尾：从能力到产品的一段

把这一程放进整套案例研究的脉络里：

- chapter-07 reviewer 走出实验室、chapter-08 用户视角走进实验室、chapter-09 副管理一日可重复、chapter-10 多证据链兜失效、chapter-11 学会收回结论；
- **本章：把验过的能力搬上货架。**

前面几章 BookScope 在学怎么得出可信的结论，chapter-11 在学怎么对待错的结论，这一章在学怎么把对的结论变成用户能用的产品。三件事缺一不可：一个只会做正确 probe 的项目是论文，一个不会收回错误结论的项目不可信，一个验了一堆能力却没一个能点的项目没产品。

这一程也暴露了"从能力到产品"那段路上最密集的坑——reasoning model 的输出层防护。chapter-11 教会项目不信任自己的测量层，这一章教会它不信任自己的输出层：模型读完全书、判断都对，但吐出来的结构化产物会截断、会被缓存 poison、章号会漂。能力对，不等于产品稳。

下一程的候选摆在 ROADMAP：设定一致性做成独立的"扫全书找矛盾"功能（差异化 A 仅剩这道没建成独立功能）、更多读者/学习者功能（时间线、论点结构）、新题材 probe（诗→意象）、以及本案例研究的继续。
