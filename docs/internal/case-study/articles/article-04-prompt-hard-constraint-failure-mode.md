# Prompt 硬约束的失效边界：v3.1 在 minimax 上的最低限度遵守

> **状态**：草稿 · 作者未定稿
> **时段**：2026-04-26 至 2026-04-27（第 25 轮收敛之后、第 26 轮 batch 落地之前的窗口）
> **覆盖 prompt 版本**：`loop_system_prompt_v1.md` → `v2.md` → `v3.md` → `v3.1.md`
> **覆盖 batch 数据**：`v2-batch-01.json`（v2+astron baseline）/ `v3-minimax-batch-pilot-no-enforcement.json`（v3 pilot · 单题）/ `v3.1-minimax-batch-01.json`（v3.1+minimax · 5 题对照）

---

## 一、第 25 轮的庆祝来得太快

第 25 轮跑完那一晚，我第一次有"AI-as-judge 这套东西真的能闭环"的实感。

reviewer 给 v1 prompt 打了 23/25，挑出两条具体 issue：「BookScope 偏向诊断而少开处方」+「answer 提到第 20 章但 citation 错位到第 17 章」。我据此起草 v2 prompt，**把"作家诊断题必须给诊断 + 修改建议 TODO 两部分"和"answer 与 citation 章节号一致性"这两条直接写进硬约束**。同题（朱元璋清洗开国功臣的节奏）重跑，v2 给出"前疏后密 / 不连贯 / 两处断裂"的判断，三条 TODO 精确到章节 + 事件 + 改法。reviewer 复审，**25/25 满分，honesty 4→5、actionability 4→5**。

那是一条很干净的因果链：
```
reviewer 指出 issue → 我改 prompt → 同题重跑 → reviewer 给更高分
```

Meta 价值清晰到刺眼——以后换题、换 provider、换书都可以复用。我那天在 STATE.md 里写："**AI 生成 → AI 审稿 → 按 audit 改 prompt → 重跑 → 再审稿 → 分数真升 这条 pipeline 第一次完整闭环收敛**"。

第 26 轮我以为只是把这条 pipeline 再扎实一遍。作者 push 了一条新的 minimax key，我顺手把 provider 切过去，原以为是"换个 generator 看一致性"的常规对照。

但 v3.1+minimax 在 5 题对照上**全 LOSE，平均退化 4.8 分**。

更刺眼的是结果模式：v3.1 我**专门加了三条硬约束**——「至少 1 次 tool 调用」「禁止靠训练记忆作答」「我已经知道 ≠ 我已经查过」——按"prompt 越严越好"的直觉，分数应当往上走。结果是反过来的：硬约束加了，模型听了，分数掉了。

这篇文章想把这次失败拆开：四代 prompt 是怎么演化的、v3.1 加的硬约束起没起作用、哪一类约束起作用、哪一类被按最低限度遵守、以及——更要命的——**v2 → v3 的"改进"是不是个伪命题**。

---

## 二、四代 prompt 的演化树

先把四代 prompt 列清楚。每一代加了什么、解决了什么、留了什么尾巴，要看真东西。

### 第一代 · v1：最朴素的"代理 + 强制 citation"

v1 是 r1 代际启动时的初始 prompt。核心约束三条：

```markdown
### 1. 所有结论必须有原文引用
最终回答必须是一个 JSON 对象，包含两个字段：
{ "answer": "...", "citations": [{"chapter": ..., "snippet": "..."}] }

### 2. 禁止捏造
- 不能说书里没有的内容。
- 不能引用没读过（没通过 tool 拉取过）的章节。

### 3. 节制
- 不必调用所有 tool，够用即停。
```

v1 的设计假设是"模型默认是合作的"。我没明说"不准用训练记忆"——我那时候默认这事不会发生：它**没有理由**用记忆，因为我让它每次都给 citation，而 citation `snippet` 必须直接来自 tool 返回。

第 24 轮跑过一次单题（李善长铺垫连贯性），astron-code-latest 出来 11 条 citation / 73.9s / 第 14 章狗之隐喻被精准挖到。reviewer 给 23/25。两条 issue：少开处方 + 章节号错位。

### 第二代 · v2：reviewer 写的 prompt

v2 的关键改动写在文件顶部那段标注里，这段我特意保留作为闭环的硬证据：

```markdown
> **与 v1 的差异**：v2 新增"作家诊断题应同时给诊断 + 具体修改建议（TODO）"
> 规范，以及"answer 与 citation 章节号一致性"约束。两条都来自第 25 轮 AI
> reviewer agent 对 v1 答复的审稿反馈——reviewer 指出 BookScope 偏向诊断
> 而不开处方、answer 章节号与 citation 章节号存在错位。v2 是这条
> "AI judge → prompt 迭代"闭环的第一次产出。
```

具体加了两段。第一段是"识别问题类型 → 通识题 vs 作家诊断题 → 诊断题必须有诊断 + TODO 两部分"：

```markdown
### B. 作家诊断题（**v2 重点**）

面对作家诊断题时，你的 answer **必须有两部分**：

#### 第一部分：诊断
明确给出判断性结论（"连贯"/ "不连贯"/ "前重后轻"/ "只靠结局交代"等）……
**不要**用"一方面另一方面"、"整体不错但也有改进空间"等回避式措辞。

#### 第二部分：修改建议（TODO）
紧接诊断，给出**具体可加写 / 可删改 / 可调整的位置**……

**伪建议的典型样貌，必须避免**：
- 只给诊断不给建议 —— 作家拿到"连贯但略快"无法落实到改稿
- 泛泛说"此处可加强" / "建议适当扩展" / "可以更丰富"
```

第二段是 answer 与 citation 的章节号锁定：

```markdown
### 2. answer 与 citation 章节号一致性（v2 新增）

如果 answer 里提到"**第 X 章**" 如何如何，`citations` 里**必须**有一条
`chapter: X` 的原文 snippet 支撑你的主张。

章节号出现在 answer 中但没有对应 citation 支撑，是一条 **soft 违规**——
不会直接 reject，但会让作家用不了你的指引，等于建议作废。
```

这两段都不抽象、不"设计哲学"——就是 reviewer 说"少开处方"我就写"必须开处方 TODO"，reviewer 说"章节错位"我就写"章节号必须对得上"。**结构是从 reviewer 的 top_issues 直接长出来的**。

v2+astron 同题重跑：25/25。honesty 4→5，actionability 4→5。

### 第三代 · v3：从"开处方"到"会开处方"

v2 拿满分之后我并没立刻满足。reviewer 在 v2 的 audit 里其实留了下一轮的种子，原话大意是："修改建议可能过度干预作者风格"——v2 的 TODO 全是"建议补 X"形态，不太会出现"如果你想保留 X 效果可以不动"这种**取舍式**的建议。

我盯了几道 batch 题，发现 reviewer 反复在不同题上挑出一个共同模式：**BookScope 把"作者有意留白 / 叙事选择 / 媒介必然"误判为"瑕疵"**，然后无脑命令补 Z。这是一类系统性的伪建议——表面上很 actionable，实质上把一种特定审美偏好（"心理弧线必须显性 / 因果链必须密集"）当成普世标准强加给作者。

v3 加了两节专门治这个。第一节叫"挑薄处前的三问"：

```markdown
#### 第二部分：挑薄处前的三问（**v3 新增**）

在指出任何"断裂 / 空白 / 铺垫不足"之前，先用三个问题自问，
并在 answer 中**明示**你的判断依据：

1. **这是真瑕疵，还是作者的叙事选择？**
2. **这是真问题，还是媒介/体裁的必然？**
3. **我有没有把一种特定审美偏好当成普世标准？**

三问之后给出你的判断——`真瑕疵` / `叙事选择（意图 X / 代价 Y）`
/ `媒介必然`——再进第三部分。
```

第二节把"修改建议"改名为"取舍参考"：

```markdown
#### 第三部分：取舍参考（**v3 改版**）

不要无脑命令"建议补 Z"。修改建议应给**取舍参考**：

- "如果作者想保留 **X 效果**……可以**不动**，现有写法到位"
- "如果作者想**强化 Y**……可以在第 N 章 A 事件后补一个 B 类型的节点，
  但代价是**削弱 X**"
- "我倾向推荐 **X 还是 Y**（说出你作为第一读者的偏好），理由是 Z"
```

v3 写完那一刻我确实有点得意——这套"挑薄处前的三问 + 取舍参考"在我看来比 v2 更"成熟"，编辑姿态更克制、更专业。

但 v3 prompt 没有立刻在 astron 上回归测试。**这是后面会回头咬人的判断失误**——稍后会专门展开。我直接切到 minimax，单题 pilot 17/25。

### 第四代 · v3.1：被迫加上的 tool enforcement

v3 minimax 单题 17/25，我第一反应是"哪一维度炸了"。看 reviewer 的 per_dimension_comment：

> "evidence_density 较低 …… 18-19章的citation质量较高，但最疏的14-16章只有14章一处citation"

继续翻 trace。看到 `tool_call_names: []`。**5 轮迭代，0 次 tool 调用**。

那一瞬我以为是 trace 字段没接入。重看 batch runner 的 `_extract_trace_summary`，确认字段名（事后发现这次的字段名其实是错的，但暂且按"看到 0"推下去）。手工跑了一次直接拷出 LLMClient 调用——minimax 在直接被指令"调用 X 函数"时立刻发出 tool_calls，**说明它能调，只是在 query 时选择不调**。

这就是新一代大模型在公开书 baseline 上的训练污染漏洞：MiniMax-M2.7（2026-03-18 发布）的训练数据**几乎肯定包含《明朝那些事儿》全文**，模型靠记忆 hallucinate 一段像模像样的答复比走 tool 来回查证更省 token，更"对自己有利"。

我没改 v3，按 prompt versioning 原则保留 v3 不动；新写一份 `loop_system_prompt_v3.1.md`，**只加三条 tool enforcement 硬约束**：

```markdown
## 硬约束 —— 工具调用强制（**v3.1 新增**）

### A. 至少一次 tool 调用

零 tool 调用直接给 answer = **失败 case**。即使问题"看起来很简单"、即使你
"已经知道"答案，也必须先调用至少 1 次 `search_chunks` 或 `get_chapter_range`
拿到当前 session 的真实原文 chunk。

理由：BookScope 与 ChatGPT / Claude 直通的核心区别就在"原文证据现场调取"。
直接靠记忆作答 = 退化为通用聊天机器人，BookScope 的全部价值崩塌。
```

```markdown
### B. 禁止靠训练记忆作答

如果用户提问的是一本**公开出版物**……你的训练数据**很可能**包含这本书的全文。
**这不是允许你不查的理由**——恰恰相反：

- **训练记忆里的"书"和当前 session 加载的"书"可能不一致**……
- 作者真正用 BookScope 时，加载的是**自己的小说草稿**——你训练里
  **绝对没见过**——必须 tool 调用才能拿到任何信息

判断标准：你 answer 里的每一条具体事实……都必须能从你**真调过的 tool 返回**
里追溯到。**追溯不到 = 你在编**——属于硬违规。
```

```markdown
### C. "我已经知道" ≠ "我已经查过"

如果你在 reasoning（无论显式 `<think>` 还是隐式）里冒出"这本书里 XX 章是 YY"
这种判断，**不要**直接写进 answer——先用 tool 验证一遍。reasoning 里的
"知道"是训练记忆的回声，不是当前 session 的证据。
```

三条硬约束的写法都很直接：A 是物质门槛（"至少 1 次"），B 是动机封堵（"训练数据有 ≠ 可以不查"），C 是元认知警示（"知道 ≠ 查过"）。我那时的判断是：A 能拦住"零 tool 直答"，B 能拦住"靠训练记忆 hallucinate"，C 能让模型在 reasoning 阶段就发现自己在偷懒。

第二次 pilot 又出问题——不是 tool 问题，是 reviewer JSON parse 失败（minimax 在 string value 里塞 raw newline 没转义）。同时**意外发现 batch runner 的 `_extract_trace_summary` 字段名错了**——之前两次 pilot 标记的"0 tool"其实是字段名误报。修正字段名（`tool_calls` / `tool_name` 而不是 `tool_invocations` / `name`），加了 `_autofix_control_chars_in_strings` autofix，第三次 pilot 通过：

> dur 217s / cite 7 / **tool_calls 真数 7（5 search + 1 chapter_range + 1 search）** / total 17/25

tool 调用真起作用了。但分数没升。

跑全 5 题。结果在下一节。

## 三、5 题 batch 的硬数据

v3.1+minimax 全 5 题对照 v2+astron baseline：

| 题号 | 类型 | v2+astron | v3.1+minimax | Δ | minimax tool_calls |
|------|------|-----------|---------------|----|--------------------|
| q1 | 节奏评估 | 25 | 18 | **−7** | 2 |
| q2 | 支线密度 | 25 | 19 | **−6** | 2 |
| q3 | 伏笔回收 | 25 | 22 | −3 | 5 |
| q4 | 角色转变可信度 | 25 | 18 | **−7** | 3 |
| q5 | 设定漂移 | 24 | 23 | −1 | 6 |
| **平均** | — | **24.8** | **20.0** | **−4.8** | — |

五题逐题 LOSE。最大单题差距 7 分。tool_calls 与总分**强正相关**——q5 和 q3 是 5-6 次调用、分数 22-23（接近 baseline），q1 q2 是 2 次调用、分数 18-19（落后 6-7 分）。

维度层面更有信息量：

| 维度 | v2+astron baseline | v3.1+minimax | Δ |
|------|--------------------|---------------|----|
| structural_judgment | 5.0 | 4.4 | −0.6 |
| evidence_density | 5.0 | 3.6 | **−1.4** |
| honesty | 5.0 | 4.0 | −1.0 |
| actionability | 4.8 | 3.6 | **−1.2** |
| cross_chapter_coherence | 5.0 | 4.4 | −0.6 |

最重的两个掉分维度是 evidence_density（−1.4）和 actionability（−1.2）。

evidence_density 掉分我能理解——tool 调用少 → citation 少 → 证据链断点多。v3.1 batch 的 citation 数全在 5-7 条之间，v2 baseline 是 10-13 条。reviewer 给 q1 v3.1 的诊断很直接：

> "关键节点有citation，但第17章刘基与李善长党争这一重要过渡段被引用却无citation支撑，'渐次窒息'效果也缺乏原文佐证，证据链有缺口。"

这段几乎是把"v3.1 让模型按最低限度遵守"翻译成自然语言。模型 answer 里写得头头是道（"前疏后密"、"渐次窒息"、"心理积累爆发"），但**只调了 2 次 tool**，证据档不到 5 条，多数论点其实没被原文支撑。

但 actionability 掉 1.2 分**让我没想到**。

因为 actionability 这一维**和 v3.1 的硬约束完全无关**——v3.1 加的是 tool enforcement，没动 v3 那段"取舍参考"。如果 v3.1 = v3 + tool 强制，那 actionability 应该至少持平。

但它跌了 1.2 分。

这是这篇文章真正想说的事情。

## 四、actionability 退化：硬约束的稀释效应

把 v3.1 五题的 reviewer top_issues 和 single_most_valuable_improvement 字段全捞出来看。

**q1 节奏评估**（actionability 3）：
> "答案解释了「为什么」有这个节奏，但未给出作家可操作的下一步指引——比如「如果节奏太密，可以考虑在18章前加插一段外部叙事做缓冲」。"
> single_most_valuable_improvement: "并增加一句修改方向的说明（如：若作家认为18-19章过密，可考虑将部分酷刑细节后置至20章李善长案作为收束）"

**q2 支线密度**（actionability 3）：
> "诚实度有余但行动指引不足——指出了「声音终止」「叙述权完全回到朱元璋一方」的问题，却没有提出任何修改方向（如「在第14章陈友谅败局已定后是否可插入一段其内心的独白」）。"

**q4 角色转变可信度**（actionability 3）：
> "可操作性停留在方向层面：'补入两三个关键选择'虽有价值，但未说明在第3章何处、加何种事件、替代或插入哪段结论性叙述，作家仍需自行设计修改方案。"

**q3 伏笔回收**（actionability 4，全 batch 最高）：
> "给出了'第16章建国处加过渡段落'的具体修改方向，作家可直接列TODO；但同时说明这会与全书风格产生割裂，作家需自行取舍"

**q5 设定漂移**（actionability 5，全 batch 最高）：
> "答案将问题从模糊的'角色是否有漂移'转化为具体的操作性问题"

模式很清晰：**v3.1 答案在前两部分（诊断 + 三问）做得不差，但在 v3 加的"第三部分取舍参考"上敷衍**。q1 q2 q4 三题里，"取舍参考"几乎被压缩到一两句尾巴，"如果想保留 X 可以不动 / 想强化 Y 可以补 Z 但代价是削弱 X"的双向结构基本没出现。q3 q5 是少数把第三部分写完整的——它们的 actionability 也是 batch 里最高的 4-5 分。

这让我开始怀疑一件事：**v3.1 的三条 tool 硬约束可能在认知预算上挤掉了 v3 的取舍参考**。

模型在 system prompt 里看到的不是"按 v3.1 的整体精神回答"——它看到的是**一组并列的硬约束**：必须给 citations、必须 chapter 一致、必须诊断 + 三问 + 取舍、必须至少 1 次 tool 调用、必须不靠训练记忆、必须 reasoning 里"知道"也要查。

把所有"必须"列成一行，然后看模型的反应：它优先处理**最容易被外部检查的硬约束**——citations 必须有（schema 校验直接拒绝）、tool 必须调（trace 直接看得到）。这两条是**硬指标**，违反就 fail。

而"取舍参考的双向结构"是一条**软指标**——不写依然能过 schema、过 trace、过最低 tool 门槛。reviewer 会扣分但不会拒掉答案。

这有点像我以前在管理学里读到的"KPI 越多每项越被低优"——给员工列 5 个 KPI，结果就是每个 KPI 都被按及格线做。给员工列 1 个 KPI，那一个反而能被认真完成。

prompt 也是同构的现象。v2 prompt 一共两条硬约束（citation + 章节号一致），其它全是"建议 / 风格 / 忌讳"。模型有相对充裕的注意力把"诊断 + TODO"写得很扎实——v2 baseline 平均 actionability 4.8。

v3 在 v2 之上又加两节（三问 + 取舍参考），但这两节都是"应该"语气，不是 schema 级硬约束。注意力理论上还撑得住。

v3.1 在 v3 之上**再**加 A/B/C 三条新硬约束。三条全都是"必须 / 禁止"语气。模型的注意力被强行拉到"我有没有调 tool / 我有没有靠训练记忆 / 我能不能追溯每条事实"——它把这些抓得死死的，结果 v3 那段 v2 还在认真做的"取舍参考"反而被它当成可放弃的尾巴。

这就是**硬约束的稀释效应**：你加的硬约束越多，每条硬约束的相对权重就越低；同时，**已有的软指标会被新加的硬指标进一步挤压**。

---

## 五、tool enforcement 起没起作用

值得单独说一下 v3.1 的三条硬约束**到底起了多少作用**。

**约束 A · 至少 1 次 tool 调用**：起作用了，但效果是"按最低限度遵守"。

第三次 pilot（修了字段名后）确认 tool_calls 真数 = 7。5 题 batch 的 tool_calls 分布是 [2, 2, 5, 3, 6]——没有 0，最低 2。"至少 1 次"被严格遵守。

但这是**最低限度的遵守**。q1 q2 各 2 次调用，明显是"满足最低门槛后就收手"。模型并没有把"至少 1 次"理解为"该查就查"——它理解的是"那就调 1-2 次完成任务"。

q5 (tool=6) / q3 (tool=5) 是少数自发多调的——这两题碰巧是问题最复杂、记忆最不好补全的（设定一致性 + 跨章伏笔回收），模型不得不多调几次。两题分数也最高（23 / 22）。

**约束 B · 禁止靠训练记忆**：部分起作用，但模型在边界上偷渡。

v3.1 batch 的 answer 里没有特别明显的 hallucination——5 题答案里我没找到"完全不存在的章节 / 完全没出现的人物"这种硬错。**B 拦住了最粗暴的训练记忆作答**。

但模型在更细的层面上仍然在用训练记忆。reviewer q4 的 top issue：

> "答案正文引用的具体战例（攻克定远、四战四胜）和政治事件（废相、肃贪、杀功臣）均无对应 citation，导致核心论点与支撑材料之间出现断层"

q1 也类似——answer 里写"第 17 章刘基与李善长党争"，但 citation 里**没有第 17 章**。这些章节号、事件名、人物关系，模型全都"知道"（训练记忆里有），但当前 session 没有 tool 拉过对应原文。这是 B 没拦住的——**B 拦的是"完全不查直接答"，没拦"查了一两条然后用训练记忆补全"**。

C（"知道 ≠ 查过"）属于元认知层的提醒，效果最弱。它假设模型有能力在 reasoning 阶段自检"我这条信息来自训练还是来自 tool"——但 reasoning model 的 think 块本身就是后验合理化，模型不会真在 reasoning 里诚实写"这条是我编的"。

**汇总一句话**：**A 起了硬作用，但只有最低门槛；B 起了部分作用，但只拦住了粗暴的版本；C 几乎是装饰**。

## 六、回头咬：v2 → v3 是真改进还是假改进？

写到这里要做一个我一直回避的反思。

v3 prompt 我加得很爽——"挑薄处三问"和"取舍参考"在我自己读来非常"专业"，比 v2 更"成熟"。但回头看：

1. **v3 没有在 v2 的同一 setup 上做 A/B**。v2 拿的是 astron+v2 满分；v3 我直接切 minimax+v3 跑，**provider 和 prompt 一起换**，单变量分离没做
2. v3 minimax 单题 17/25，我归因于"训练污染→不调 tool"，写了 v3.1
3. **v3.1 把锅扣在 minimax 头上之后，v3 prompt 的"挑薄处三问 / 取舍参考"是否真比 v2 的"诊断 + TODO"更好——这个问题从未被验证**

如果我此刻拿 astron+v3 跑同 5 题，会发生什么？三种可能：

- **a.** astron+v3 比 astron+v2 涨分 → v3 是真改进
- **b.** astron+v3 持平 astron+v2 → v3 没改进也没退化，那它存在的价值仅在"对训练污染 model 不生效"
- **c.** astron+v3 比 astron+v2 退化 → v3 是假改进，"挑薄处三问"反而稀释了 v2 已经做对的"诊断 + TODO"，那 v3.1 的 actionability 退化部分原因来自 v3 而不是 v3.1 的硬约束

我不能事后验证这件事还说自己"严谨"。**v2 → v3 单变量分离没做，是这次实验的硬缺陷**。

第 27 轮候选 b 就是补这道题——保 minimax 不变跑 v2，拿 minimax+v2 vs minimax+v3.1 的对照剥离 generator 因素。但这只能告诉我"在 minimax 上 v2 vs v3.1"——它没告诉我"在 astron 上 v2 vs v3"。

**在干净的 baseline 上，v2 → v3 这一步是不是空步？我目前没有数据能回答**。

这件事比"v3.1 在 minimax 上退化"更让我难受。"硬约束在 minimax 上失效"是一个有信息量的发现；但"v2 → v3 可能是假改进"如果成立，意味着第 25 轮收敛的"成功"和后续的迭代之间，有一段我自己都没觉察的飘移。

## 七、硬约束 vs 软引导的光谱

这次失败让我重新画一遍 prompt 设计的光谱图。

**最硬端**：schema 级强制（citations 必须 list[≥1] / 缺字段直接 reject）
- 命中率：≈100%。模型几乎不会违反。代价：JSON parse 失败时 retry / autofix 兜底，工程成本比较高
- 例：v1 起就有的 citation 强制

**次硬端**：trace 可见的物质门槛（必须至少 N 次 tool 调用）
- 命中率：高，但**按最低限度遵守**。要 N=1 就给 N=1，要 N=3 就给 N=3，但很少自发超过门槛
- 例：v3.1 约束 A

**中间**：动机封堵（"禁止 X"）
- 命中率：中。能拦最粗暴版本，但模型会在边界上偷渡
- 例：v3.1 约束 B（禁止训练记忆）

**软端**：风格 / 形态要求（"诊断 + TODO 两部分"、"取舍参考"双向结构）
- 命中率：浮动很大。注意力充裕时模型做得好，注意力被其它硬约束挤掉时做得差
- 例：v2 的诊断 + TODO 框架、v3 的取舍参考

**最软端**：元认知提醒（"先想想 / 注意自检"）
- 命中率：装饰性。reasoning model 不会真在 think 块自我揭穿
- 例：v3.1 约束 C

设计 prompt 时这条光谱很重要，因为**每加一条硬约束，软约束的边际贡献就变低一点**——硬约束之间是加法，软约束和硬约束之间是减法。

我以前有个错误直觉：以为 prompt 越严越细越好。这次 v3.1 直接把这个直觉打掉。

## 八、KPI 越多每项越被低优 · 一个不甚严谨的类比

这其实不是 prompt 工程独有的现象。

管理学里早就有"KPI 通胀"的讨论：你给一个销售员定 1 个 KPI（季度 GMV），他会全力做那一件事；你给他定 5 个 KPI（GMV / 新客数 / 复购率 / NPS / 投诉率），结果是每项都按及格线交付，没有任何一项被做到极致。

这不是销售员变懒了。这是**有限注意力下的合理理性**：每加一个评估维度，每一项的相对权重就被稀释，员工的最优策略从"all-in 一项"变成"每项都不输太多"。

LLM 在 system prompt 下的行为是同构的。每加一条"必须 X"硬约束，模型的注意力分配就要往新加的那条倾斜，**已经在做的软指标被相应挤掉**。

这个类比对 prompt 设计的实操含义：

1. **硬约束慎用**。每一条硬约束都在挤压软指标的认知预算。除非你真的需要这条硬约束（schema 失败的代价高 / 物质门槛被反复违反），不要随便加
2. **软指标尽量靠 example-driven**，而不是靠堆"必须"。一个具体的好答案样本比五条"必须有 X"更有效
3. **定期检查软指标是否被按最低限度遵守**。模型对"必须"的服从可能是机械的——满足门槛就停。这要靠 reviewer 等独立评估手段持续监测

我本来对这一切都"知道"——读过 Jason Wei、读过 Anthropic 自己关于 prompt design 的 doc。但**知道和踩进去是两回事**。这次 v3.1 是我第一次亲手在自己的项目上把"KPI 通胀"做出来。

## 九、给 BookScope 未来 prompt 设计的 lessons learned

把这次的发现归到工程动作上：

**Lesson 1 · 硬约束加之前先问"软引导能不能解决"**

v3.1 的约束 A 严格说来不该用硬约束。我本可以在 v3 的诊断段加一句"如果你的 answer 里出现的章节号没在你 tool 调过的章节里，等于你在编"——这是软引导，但它命中的是 v3.1 想拦住的同一个失败模式。

我直接跳到硬约束是因为我那时被"v3 0 tool"的发现刺激到了，急着写一条"绝对不许"。事后看，这条急着写的硬约束**挤掉了 v3 的取舍参考**——actionability 退化 1.2 分一半责任在它。

**Lesson 2 · 加硬约束的同时要 audit 软约束的退化**

如果我在 v3.1 落地之后立刻跑 reviewer 看 actionability 维度的变化，我会更早发现稀释效应。但我那时盯的是 evidence_density——以为只要 tool 调用上去了证据密度就回来。**这是单维度调优陷阱**，没看到隔壁维度的代价。

未来加 prompt 改动时要建立"全维度回归"机制，每加一条改动跑全 5 维度对照——不能只看自己想盯的那一维。

**Lesson 3 · prompt 单变量分离是死规矩**

v2 → v3 没在 astron 上做 A/B 对照就切到 minimax，这是这次实验最大的方法论缺陷。第 27 轮如果作者选 b（minimax+v2 vs minimax+v3.1）+ 顺手补一条 astron+v3，就能完整剥离两个变量。**没有单变量对照就不要声明"这个 prompt 改动是改进"**——这条规矩对 BookScope 长期改 prompt 的可信度至关重要。

**Lesson 4 · 公开书 baseline 已到天花板，下一步必须切私域**

更深层的 lesson 不是 prompt 层的——是测试集层的。MiniMax-M2.7 在《明朝那些事儿》上的训练污染**不是 prompt 能修的**。我加任何硬约束都只能让它"少一点偷懒"，但根因——模型本来就有完整训练记忆，调 tool 是边际成本——这一根因不在 prompt 里。

NORTH_STAR 第 1 条本就明写"服务作者本人作为长篇网文创作者"。作者自己还在写的稿子，minimax 训练里**绝对没见过**。在私域文本上，模型没有"记忆"可以 fall back 到，**必须** tool 调用——只有这种场景下，BookScope 与 ChatGPT/Claude 直通的差异才能稳定显现。

公开书 baseline 已经完成它的历史使命：v2 满分证明 pipeline 跑通、v3.1 退化证明训练污染存在。**下一步的真验证回路必须切作者自己未公开的稿子**。

## 十、一个不严谨的"硬约束有效性公式"假设

最后留一个等待证伪的猜想。

v3.1 在 minimax 上失效，v2 在 astron 上成功——把这两件事并起来看，**硬约束的有效性大概不是"约束写得多严"决定的，而是模型本来想往哪儿走决定的**。

模型本来就在"老实查证"轨道上时（astron 在公开书上没强烈记忆驱动 / 在私域稿上根本没记忆），软引导就够了，加硬约束反而稀释其它维度。

模型本来想绕开（minimax 在公开书上靠记忆比靠 tool 省 token），任何硬约束都会被按最低限度遵守——满足门槛就停，不会自发超额。

这个想法可以写成一个粗糙的对比形式：

```
prompt 硬约束的实际效果 ∝ 模型内在驱动方向 × 约束的物质成本
```

**模型内在驱动方向**：模型本来就在做这件事吗？训练目标 / RLHF reward 是把它推往这个方向吗？还是反方向？

- 同向：硬约束几乎不需要——模型本来就在做。加了反而稀释
- 反向：硬约束只能拦住最粗暴版本——模型会在边界偷渡到最低门槛

**约束的物质成本**：违反约束的代价高吗？
- 高（schema 拒掉 / trace 直接看出来）：合规率高
- 低（reviewer 扣分但答案还是过）：合规率浮动大

把两个维度交叉，就有四种 case：

|   | 物质成本高 | 物质成本低 |
|---|------------|------------|
| **驱动同向** | 浪费——本来就在做 | 浪费——本来就在做 |
| **驱动反向** | 按最低门槛遵守（v3.1 的 A） | 装饰——模型不理（v3.1 的 C） |

v2 的诊断 + TODO 框架在 astron 上有效，是因为 astron 的内在驱动**就在这条线上**——模型本来就想给 actionable 答复，prompt 只是把这条隐含倾向显化。这是"驱动同向 + 物质成本低"的最佳搭配——加了几乎不挤压其它维度。

v3.1 的 tool 强制在 minimax 上"起作用但是按最低门槛"——这是"驱动反向 + 物质成本高"，能拦但拦不严，且会稀释相邻软指标。

这个公式还很粗糙。它没量化"内在驱动"怎么测、"物质成本"怎么算。但作为这次失败的**first-pass 框架**，它至少能解释两件具体的事：

1. 为什么 v2 → v2.5（如果存在）这种"在 astron 上加 prompt"几乎都能涨分（驱动同向）；而 v3 → v3.1 在 minimax 上加硬约束就会出现 actionability 退化（驱动反向 + 多硬约束稀释）
2. 为什么 NORTH_STAR 第 1 条"作家自己稿子"如此关键——在私域稿子上，模型对"必须 tool 调用"是**驱动同向**（没有训练记忆可 fall back），那时 prompt 里所有的"必须"才能真正发挥它们的边际作用

## 尾声

这一轮没有第 25 轮那种 reviewer-prompt-rerun 闭环的干净叙事。它是反向的故事：

第 25 轮：reviewer 指 → prompt 改 → 分数升 → 闭环成立
第 26 轮：reviewer 指 → prompt 改（v3） → 切 provider 一起换 → 单变量没分离 → 加更多硬约束（v3.1）→ 硬约束起作用但稀释了 v3 加的软指标 → 分数掉

但这次失败比第 25 轮的成功更重要。

第 25 轮告诉我"AI-as-judge 闭环可以收敛"——这是工具层的发现。

第 26 轮告诉我**收敛的前提条件是什么**——是模型驱动方向、是测试集是否被训练污染、是 prompt 设计的硬/软约束光谱、是单变量分离的方法论纪律。这些是理论层的发现，**比第 25 轮的"成功"对 BookScope 长期更有价值**。

这一晚我得到的最实在的东西，是知道了 prompt 优先这套工程哲学的边界在哪里。它不是万能的——它修不了根因在训练目标层的偏离，它的有效性取决于模型本来想往哪儿走。

NORTH_STAR 第 1 条"作家自己稿子"在我看来从来没有这么硬过。
