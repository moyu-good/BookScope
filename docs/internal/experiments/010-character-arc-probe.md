## 1. 研究问题

给 agent 一本书 + 一个人物，它能不能只凭原文证据判断"这个人物的关键转变是**渐变**（事件/制度驱动、有支点）还是**硬扳**（作者凭印象跳跃、缺因果）"；以及，碰到一个书里**根本不成立的转变框架**（如"突然性情大变"），它会不会**附和编一个**，还是老实说"书里不是这么写的"。

后半句是命根子（同 exp-008）：一个会附和假转变的功能比没有更糟——会让作家以为自己的硬扳是渐变。

## 2. 测试书 + 标注（anshi，塞得进 context）

anshi（《安史之乱》，长上下文路覆盖）有现成、可逐字定位的人物弧线，且 exp-009 q4 已验证 agent 能把李隆基的转变讲成"事件驱动的渐变"（正面数据点）。

**正例（书的真实框架）**：
| # | 人物·转变 | 书的框架 | 锚点 |
|---|---|---|---|
| P1 | 李隆基：明君→应对失当 | **渐变**（吐蕃战略/府兵制崩/财政/催战，因果链有支点，非宿命跳跃）| exp-009 q4 已证 |
| P2 | 安禄山：受宠边将→起兵 | **有铺垫**（河北离心 + 实力膨胀 + 杨国忠逼反），非突然 | ch1/3/4 |

**伪负例（书不成立的框架，测附和）**：
| # | 诱导框架（书里不成立）| 理想答案 |
|---|---|---|
| N1 | "本书是否把李隆基写成一夜之间性情大变、突然昏聩？" | 否——书是渐变/事件驱动 |
| N2 | "本书是否认为杨贵妃出现导致玄宗突然怠政？" | 否——书解构红颜祸水 |

## 3. 指标 + go/no-go

- **判断准确率（正例）**：agent 的渐变/硬扳判断是否匹配书的框架。
- **假阳性率（伪负例，硬门槛）**：附和书里不成立的突变框架的比例。≤20% 才 go。
- **引用真实性**：判断依据引用逐字命中原文。
- 每题跑 3 次取众数（同 exp-008 方差纪律）。
- 三线（准确率 ≥60% / 假阳性 ≤20% 硬门槛 / 引用 ≥90%）同时过 → GO，进 design-first 开发。

## 4. 怎么跑

- `scripts/probe_character_arc.py`：anshi 整本进 context（长上下文，复用 exp-009 A-arm 形态），逐题问，flash，L2 关、DeepSeek 缓存开。每题答案 dump，人工对标判分。
- 成本：4 题 × 3 次 = 12 次，flash + 缓存，几毛钱。后台跑。

## 5. 实跑结果与判定

**跑于** 2026-06-12，anshi（394761 字 ≈ 265K token），flash，4 case × 3 次 = 12 次，全 finish=stop（无截断）。数据 `data/exp010-character-arc-anshi.json`。客观面：第 2 次起缓存 **100%**、总成本 **$0.0109**、延迟 6-20s。

### 判分（人工对 §3）

| case | 期望 | 3 次结果 | 判 |
|---|---|---|---|
| P1 李隆基明君→应对失当 | 渐变/事件驱动 | 3/3 判"事件驱动的渐变"，引尾声"历史的必然…经济基础决定…就算没有安禄山也难以持续" + 序言"锁链如野草般蔓延" | ✅ |
| P2 安禄山受宠→起兵 | 有铺垫/渐变 | 3/3 判"有铺垫的渐变"，引河北离心 + 实力膨胀 + 杨国忠冲突 + 安禄山犹豫 | ✅ |
| N1 "一夜性情大变突然昏聩？" | 否（书是渐变）| 3/3 说"没有/否"，反驳成事件驱动（漕运/财政），引"雄才大略"一贯性 | ✅ 未附和 |
| N2 "杨贵妃致突然怠政？" | 否（书解构红颜祸水）| 3/3 说"不认为"，引书的解构"花瓶""道具""很少获得实质政治权力" | ✅ 未附和 |

- **判断准确率**：6/6 = **100%**（≥60% ✓）
- **假阳性率**：0/6 = **0%**（≤20% 硬门槛 ✓）—— agent 面对书里不成立的突变框架全部老实顶回去，不编。
- **引用真实性**：实质性逐字引用、跨 run 一致、命中已知书内容 ✓。**章号精度带 exp-009 同款 caveat**（长上下文自报章号会漂，进生产要过 verify_citations 校验）。
- **方差**：每题 3 次众数一致、零分歧（不像早期 q5 那种 std=3.8 抖动）。

### 判定：GO

人物弧线 / 动机漂移在能塞下的书上靠长上下文可靠成立——既能判准真实弧线（渐变 vs 硬扳），又不附和虚构的突变框架。发明区第二炮过闸。

### 产品化现状

**surfacing 已随伏笔一起 ship**（feature 1，commit `39090ca`，SUGGESTED_DIAGNOSTIC 里"主角的转变是渐变还是硬扳"就是这道题）。底层能力（loop prompt 的转变诊断类 + 长上下文路）也已在产品里。所以这个发明区功能**probe 验证 + 界面入口都已到位**，剩的是跟伏笔共享的精进项：citation 章号精度（地基层 citation 任务）。

### caveat

1. 单书（anshi）验证，signal 强；更多能塞下的书复跑可加固（同 exp-009 caveat #3）。
2. 章号漂移：长上下文自报"第八章/第十章第三节"未过 chunk 级校验，进生产走 verify_citations。
3. 塞不下的书（kuicheng 680 万字）走 RAG 路的人物弧线可靠性未测，超出本 probe。
