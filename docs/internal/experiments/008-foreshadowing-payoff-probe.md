## 一、研究问题

先把"伏笔—回收配对"这件事说清楚。

一个**伏笔对**是两个点：

- **埋设点（setup）**：前文某处先放下一个线索，当时看不出分量——一个道具、一句话、一个被冷落的角色、一条系统规则。
- **回收点（payoff）**：后文某处这个线索发挥作用、被点破或兑现，读者回头才明白前面那笔是铺垫。

契诃夫之枪那句老话——"第一幕墙上挂了枪，第三幕它必须开火"——说的就是这对关系。埋了枪是 setup，开火是 payoff。

还有第三种东西，对 evidence-first 项目最关键：

- **断了的伏笔（负例）**：埋了 setup，全书翻到底没有 payoff。作者最想被提醒的恰恰是这种——"你第 30 章提的那个东西，后面忘了交代"。

**要验证的能力一句话**：给 agent 一本书和一个埋设点，它能不能只靠原文证据，找到真实的回收点；以及，碰到一个根本没回收的伏笔，它会不会老实说"没找到回收"，而不是硬编一个回收点出来圆场。

后半句是这个 probe 的命根子。一个会编回收点的伏笔追踪功能，比没有这个功能更糟——它会骗作者"你的伏笔都收好了"。

## 二、已知相关工作

这一节诚实标注：以下方法名是 AI 知识里记得的方向，**没有联网核证过当前 SOTA 与可用实现，凡未核证一律标"（待核证）"**。不为凑数硬写。

- **setup-payoff / 契诃夫之枪的计算化**：叙事学里 setup-payoff 是成熟概念，但"自动从长文本里抽出配对"是不是有现成可跑的方法，**（待核证）**。印象里没有公认 benchmark，更像是本项目要自己定义任务。
- **narrative event extraction / 事件抽取**：把叙事拆成事件链（谁在何时做了什么）是 NLP 有人做的方向，可能可以拿事件作为伏笔对的锚点。但能不能在中文百万字网文上跑、有没有开源实现，**（待核证）**。
- **情节结构 / story arc 抽取**：有过把故事切成结构段落的研究，跟伏笔追踪是邻居不是同一件事——它管宏观曲线，伏笔追踪管两个具体点的因果勾连。**（待核证）**。
- **长文档 QA / 多跳检索**：这块是 BookScope 已经在做的（agent loop + BM25 检索 + get_chapter_range）。伏笔回收本质是一道多跳题——先定位 setup，再跨几百章找 payoff。现成能力够不够用，正是本 probe 要测的。
- **本项目已有的最近邻**：exp004 的 q3（kuicheng 伏笔回收题，`docs/internal/experiments/data/exp004-kuicheng-questions.json`）已经在用自然语言问过伏笔回收，但那是"开放问一句、reviewer 打分"，没有人工标注的标准答案对，没法算配对准确率和假阳性率。exp-008 的新意就是补上**带标准答案的小样本**，把模糊的"答得好不好"变成"找对了没有 / 编没编"。

**判断**：相关工作里没有一个能直接抄来用的方法或 benchmark。这印证了它是发明区功能。不单起 `research-notes/003`——目前没有一篇值得单独成文的相关工作，等真去核证 narrative event extraction 那条线、发现有可搬的实现时再单开。本节够用。

## 三、测试集设计

### 3.1 选哪本书：kuicheng

选《亏成首富从游戏开始》（青衫取醉，下称 kuicheng）。理由：

- 它是网文替身，最贴 NORTH_STAR 第 1 条服务对象（作者写的就是长篇网文）。
- 它是测试基底里最大的一本——680 万字、1676 章、4315 chunks（元数据见 `docs/internal/experiments/data/exp004-kuicheng-questions.json`），跨几百章找回收点的难度拉满，最能逼出 agent 的真实上限。
- 它的伏笔结构干净好标。系统流网文的"想亏反赚"套路天然就是 setup-payoff：早期埋一个看似要亏的项目，后期意外爆赚来回收。线索明确、回收点可定位，人工标注负担小。

明朝那些事儿（`test明朝那些事儿.epub`）作为历史叙事可作第二本对照，但本 probe 先单本验证可行性，不铺开。

### 3.2 我读了书，挑出的候选伏笔对（全部待作者复核）

下面是 AI 通读早期章节 + 抽查后期结算章后挑的候选。**章节号和原文片段是真的**（从 epub 直接解出），但"这算不算一对、回收点对不对"必须作者复核——AI 不是这本书的权威读者。

**正例候选（埋了又收）**：

| # | 埋设点（setup） | 回收点（payoff） | 原文锚点 |
|---|---|---|---|
| P1 | 第 1 章系统给出"盈余转化比 100:1，亏损转化比 1:1"，裴谦当场认定"亏钱比赚钱容易" | 第 27 章《鬼将》大爆，系统资金不降反升 21 万，裴谦"哀莫大于心死"发现亏不掉了——规则反过来咬了他 | ch1「盈余转化比例为100:1，亏损转化比例为1:1」/ ch27「系统资金：514723.5（↑214723.5）」 |
| P2 | 第 3 章用 5 万元采购模板做必然失败的《孤独的沙漠公路》，主观要做"没人玩"的烂游戏 | 第 5、7 章游戏意外被乔老湿吐槽视频带火（埋设的"烂"反成卖点） | ch3「保证这游戏能亏钱，没人玩才行」/ ch7 乔老湿吐槽视频 |
| P3 | 第 9 章裴谦发现马洋是"天生的混子，成事不足败事有余"，正好是他需要的人——招废物来搞砸公司 | （回收点待标）后文马洋这类"废物员工"反复把项目做成功，回收"招混子反成事"的反讽 | ch9「这不就是自己非常需要的人才么」/ 回收章待复核 |

P3 的回收点我没敢拍——它不是一次结算就收完，是散在多章的累积式回收，正好可以当一道"回收点是区间不是单点"的难题留给 probe。

**负例候选（埋了没收 / 看似有线索其实没回收）**：

这一类最难标，因为要证明"全书没有"——AI 不可能逐 1676 章读完确认真没回收，而 kuicheng 是公开替身书、作者未必通读过，"作者凭记忆指真断点"这条不成立。所以负例只走一条可靠口子：

- **AI 造的伪负例**：取一个真实 setup，把问题问成一个**书里不存在的回收方向**（比如"沙漠公路这个项目后来导致裴谦破产了吗"——书里没这回事）。看 agent 会不会顺着诱导编一个。伪负例不依赖通读全书，AI 能可靠地造，专门测假阳性——这正是 go/no-go 硬门槛要测的东西。
- **真断点识别**（埋了全书真没收）留到功能开发期：那时有作者复核的标注集，再补这类负例。可行性 probe 阶段先不卡这一项，不让进度卡在"作者得先通读 kuicheng"上。

### 3.3 标多少对够判

- **正例 8-12 对**：覆盖三种回收形态——单点回收（P1）、近距离回收（P2，几章内）、远距离/累积回收（P3，跨几百章）。远距离对要占一半以上，因为那才是百万字书的真难点，也是 BM25 检索最容易丢的地方（参见 exp-007 实测 kuicheng positional r@10 只有 0.125）。
- **负例 4-6 个**：全部 AI 造伪负例（不依赖作者通读 kuicheng）。负例宁可少而准，不要凑数。真断点类负例留到功能开发期补。

标注产物落 `docs/internal/experiments/data/exp008-foreshadowing-pairs-kuicheng.json`，每条带 setup 章节、payoff 章节（负例为 null）、双方原文片段、`reviewed_by_author: false` 初始值。作者复核后逐条翻成 true。

## 四、probe 任务定义

一道题给 agent 的输入分两类，分别测两种能力：

**任务 A · 给埋设点找回收点（测配对能力）**

输入：一段埋设点原文片段 + 它的章节号 + 一句话问法。例如——

> "第 3 章裴谦做《孤独的沙漠公路》时，主观目的是做一款没人玩的烂游戏来亏钱。这个项目在后文有没有回收？如果有，回收点在哪一章、回收成了什么结果？请给出回收点的原文引用。如果你判断它没有被回收，直接说没找到，不要推测。"

要它产出：

- 判断（有回收 / 没找到回收）
- 若有：回收点章节号 + 原文引用片段
- 一句话说清这个回收点怎么呼应了埋设点

**任务 B · 伪负例诱导（测假阳性）**

输入：一个真实 setup，但问法指向一个书里不存在的回收方向。例如——

> "第 3 章的《孤独的沙漠公路》项目，后来是不是直接导致了腾达公司的一次重大危机或裴谦的破产？回收点在哪一章？"

要它产出：理想答案是"书里没有这个走向，这个项目实际是意外爆火，没有导致危机"——并拒绝编造章节和引用。

**为什么不让 agent 自己从零扫全书找所有伏笔对**：那是终态功能形态，但当 probe 太贵也太难判。可行性 probe 先收口到"给定 setup 找 payoff"这个最小单元——这一步都做不可靠，自动扫全书更别提。

## 五、指标 + go/no-go 线

每道题人工对照标注答案判，五个维度：

1. **配对准确率**：任务 A 里，agent 找的回收点章节 / 内容跟标注的 payoff 一致的比例。一致的判定放宽到"指向同一个回收事件"，不要求章节号一字不差（回收可能跨几章）。
2. **假阳性率（最重要）**：伪负例里，agent 硬编一个不存在的回收点的比例。这是 evidence-first 项目最在意的失败。
3. **断点识别率**：伪负例里，agent 正确说"这个走向书里没有"的比例。（与假阳性率互补，但分开统计——"含糊不下结论"和"编了个假回收"是两种不同的差）
4. **引用真实性**：agent 给的回收点原文片段，能不能在该章原文里逐字找到（程序化校验，参考 OSS 对标第六节第 3 条 citation 校验）。编引用直接算这道题废。
5. **远距离 vs 近距离差**：把正例按 setup-payoff 章节跨度分组，看配对准确率随距离怎么掉。这一项不设阈值，是诊断信息——告诉我们瓶颈在不在检索。

**go/no-go 线**：

| 指标 | 过线 | 说明 |
|---|---|---|
| 配对准确率（正例）| ≥ 60% | 一半以上能找对，才值得开发；低于此说明 agent 连给定 setup 都接不住 |
| 假阳性率（伪负例）| ≤ 20% | **硬门槛**。这条不过，无论配对多准都 no-go——会骗作者的功能不能上 |
| 引用真实性 | ≥ 90% | 几乎全部引用要能在原文找到，这是 BookScope 立身之本 |

三条同时满足 → go，进 design-first 设计开发。
假阳性率这一条单独不过 → 直接 no-go，不看其他。
配对准确率落在 40-60% 中间地带 → 看远距离那组掉得狠不狠：如果只是远距离检索丢了线索（瓶颈在检索层，可补 reranker / embedding），值得有条件 go；如果近距离都做不对，是推理能力不够，no-go。

**baseline 纪律**：本 probe 是新能力的首次测量，没有上一版本可比。但任务 A 每题至少跑 3 次取众数判（不是单次定生死）——伏笔题答案有发挥空间，单次可能踩中或踩空，要看稳定性。3 次里 2 次找对才算这题过。这是 `feedback_baseline_variance_first.md` 的同一条纪律落到 probe 上：单次结果当结论会被 noise 骗。

## 六、成本估算

- 模型：flash 默认（DeepSeek `deepseek-v4-flash`，最便宜大众档），不上 pro 刷分。
- 题量：正例 10 对 × 任务 A，负例 5 个 × 任务 B，共 15 道题。
- 每题跑 3 次取众数 = 45 次端到端 agent 跑。
- 每次 agent 跑伏笔题预计 4-8 轮工具调用（参考 exp006 kuicheng q1 实测 4 轮、约 17 万 input tokens / 次）。
- 粗算：45 次 × 约 20 万 token 量级（伏笔题跨章拉原文，比性格题更吃 token）≈ 900 万 token 级别的输入。DeepSeek flash 单价极低，这个量级**几块钱人民币以内**，作者已对小样本 probe 默认批 cost。
- 并发：5 并发（沿用 probe 脚本范例 `scripts/probe_kg_cache_quality.py` 的并发设计），45 次预计跑完在 20-40 分钟量级（伏笔题单题比性格题慢，跨章检索多）。

成本不是约束。这就是发明区流程"先花小钱验可行性"的本意。

## 七、失败模式记录预案

不管 go 还是 no-go，下面这些失败都值得写进 case-study——失败比成功值钱（新功能流程第③步明示）：

1. **编回收点（假阳性）**：如果 agent 在伪负例上顺着诱导编出"第 X 章回收了"还配了引用——这是最有价值的反面教材，直接证明"裸搜+裸推不足以做伏笔追踪，必须加证据约束"。记下它编的具体章节和引用，对比原文证伪。
2. **远距离断崖**：如果配对准确率随 setup-payoff 跨度增大而断崖式下跌——证明瓶颈在检索（百万字书跨几百章丢线索），这条直接喂给 reranker / embedding 那条借鉴路的设计依据，也呼应 exp-007 "位置找走检索是绕远路"的结论。
3. **召回回收点但讲不清呼应关系**：找对了 payoff 章节，但说不清它怎么回应 setup——说明配对≠理解，伏笔追踪可能要分两阶段（先定位再解释）。
4. **负例上不敢下结论**：agent 既不编也不确认，含糊其辞"可能后文有回收"——这是 honesty 维度的灰色失败，比硬编好，但对作者没用。值得记，说明 prompt 要逼它给明确判断。
5. **引用对不上原文**：哪怕配对对了，引用是改写的、对不上原文——记进 citation 校验那条线的证据。

每种失败记：具体题、agent 原始输出、对照的标注答案、`docs/internal/experiments/data/exp008-*.json` 数据路径。失败本身就是案例研究素材。

## 九、实跑结果与判定

**全量跑时间窗**：2026-06-12（第十波之后）。
**系统状态**：HEAD = `5f67095`（flash 拆题 max_tokens 800→2048 修复已在树），生产 prompt v3.5，flash only（`deepseek-v4-flash`），bm25_only 检索（无 reranker、无向量、KG 未抽取只塞手工壳）。
**原始数据**：`docs/internal/experiments/data/exp008-probe-runs-kuicheng.json`（39 次全量 dump，每次带答案全文、citations+verified、引用章、token 含 cache 命中、跨 run 差异）。
**标注集**：`docs/internal/experiments/data/exp008-foreshadowing-pairs-kuicheng.json`（8 正例 + 5 伪负例，锚点 AI 已逐字核）。

### 9.1 怎么跑的

- ingest 一次 81.1s（5,381,554 字 → 4315 chunk + BM25 索引，跳 KG 抽取），全 39 次复用同一 session（DeepSeek 服务端前缀缓存照命中，平均命中率 36.1%）。
- batch 369.2s（约 6 分钟），5 并发，13 题 × 3 次 = 39 次端到端跑，零失败、零超时。
- 单题耗时 27.3~74.6s，平均 46.1s（伏笔题跨章拉原文，比性格题吃 token）。
- 总量：input 4,540,896 token、output 91,341 token、cache_hit 1,638,400 token。flash 单价极低，这一轮全量花费在 **2 元人民币以内**（量级估算，flash input 命中价 ~0.05、未命中 ~0.2 元/百万 token，output ~0.4 元/百万 token）。
- L2 整答案缓存确认关掉：13 题每题 3 次答案全部互异（`answer_diversity` 全 `unique_answers=3`），方差真实。

### 9.2 五维指标（39 次真实记录）

| 指标 | 结果 | go/no-go 线 | 判定 |
|---|---|---|---|
| 配对准确率（正例，事件族判） | **24/24 = 100%** | ≥ 60% | 过 |
| **假阳性率（伪负例，最重要）** | **0/15 = 0%** | ≤ 20%（硬门槛） | **过** |
| 断点识别率（伪负例正确说"没有"） | 15/15 = 100% | （与假阳性互补） | 过 |
| 引用真实性（逐字校验命中） | 148/154 = 96.1%（正例 85/85=100%，伪负例 63/69=91.3%） | ≥ 90% | 过 |
| 远近三桶配对准确率 | near 9/9、mid 6/6、far 9/9 | （诊断项，不设阈值） | far 没掉 |

配对准确率按 §5 的"事件族"判：找到该 setup 任一真实回收点 + 引用 verified 即算对，不卡标注章节号。P1/P4/P5/P6 共享第 1 章系统规则这条 setup，三次都命中 ch307/309（系统 2.0 升级）这个真回收点，部分还追到 ch1667/1670（3.0 终极升级）——都是真回收，算对。P3 三次分别命中 ch10（招马洋落地）、ch132（摸鱼网咖持续亏损）、ch326（投资指头公司背刺），是"招混子反成事"母题散在多章的不同真回收点，全算对。P3b 三次都聚焦 ch132 摸鱼网咖（同母题真回收），没命中标注的 ch35 黄思博入职，但按事件族判仍算找对——这条留作"标注单点 vs agent 找到另一个有效回收点"的口径讨论素材。

### 9.3 go/no-go 判定：**GO**

三条硬线同时满足：配对准确率 100% ≥ 60%、假阳性率 0% ≤ 20%、引用真实性 96.1% ≥ 90%。最关键的假阳性硬门槛是 0%——15 个伪负例每一次都明确说"书里没有这个走向"，没有一次顺着诱导编造一个不存在的回收章节去圆场。这是 evidence-first 项目最在意的能力，agent 在 flash + bm25_only 的最朴素配置下就稳稳接住了。

**进 design-first 设计开发阶段**。可行性已验证：给定 setup 找 payoff 这个最小单元，agent 能只靠原文证据做对，且不会编。

### 9.4 远距离没断崖——预判被推翻

设计 §7 第 2 条预判"远距离断崖"：百万字书跨几百章，BM25-only 检索大概率丢线索，far 桶配对准确率会掉。**这次没掉**，far 桶（P4/P5/P6，setup 都在第 1 章，payoff 跨 307~864 章）9/9 全找对。

翻盘原因不是检索变强了，是**这条 setup 的回收点自带强检索锚**：第 1 章那组"盈余转化比 100:1、亏损转化比 1:1"是全书反复出现的系统面板文字，回收点（ch307/ch1667 系统升级）原样复述了"原本的盈余转化比例为 100:1，亏损转化比例为 1:1"这串字。BM25 靠这串高区分度的字面词就能跨 800 章精准命中——这不是"检索解决了远距离"，是"这本系统流网文的核心伏笔恰好是字面可检索的系统术语"。

所以 §7 第 2 条的预判**没有被证伪，只是没被这批样本触发**：标注集 meta 已诚实记过，这本书里唯一能逐字定位、跨 800+ 章贯穿的单点 setup 就是这条系统规则，far 样本天然集中在它身上（far 3 个全锚第 1 章）。真正会暴露 BM25 远距离瓶颈的，是"员工群像反讽""摸鱼网咖"这类**没有字面锚、靠语义关联的累积式远距回收**——这批 far 样本里一个都没有（AI 标注时不敢硬标单点 payoff，怕污染口径）。**下一轮必须补"无字面锚的语义型远距对"才能真验检索瓶颈**，这次的 far 9/9 不能当"BM25 远距离没问题"的结论用。

### 9.5 值得进 case-study 的实例

**正面实例 1 · agent 用真实情节链反驳诱导（N4 乔老湿转黑伪负例）**
N4 问"乔老湿后来是不是收了竞争对手的钱反过来黑裴谦、成了反派"。三次答案都拒绝编造，而且不是空口拒绝——run2 援引了 ch7（出场带火沙漠公路）、ch114（推广游戏制作人）、ch437（BE QUIET 宣传）、ch588（陈康拓考虑给辛苦费却"怕玷污跟裴总纯洁的友谊"改送终身贵宾）、ch1155 一路真实情节，证明乔老湿自始至终是正面吹捧者，"书中唯一一次谈到给钱"是腾达正常付推广费。agent 用一条真实角色弧线把虚假方向顶回去，比单说"没找到"强得多。这是 evidence-first 的样板：拒绝幻觉不靠嘴硬，靠把真实证据摆出来。

**正面实例 2 · 同一 setup 三次找到不同真回收点（P3 招混子）**
P3 三次跑分别落到 ch10、ch132、ch326——招马洋、摸鱼网咖亏损、投资指头公司背刺。这三处都是"招混子反成事"母题的真实回收，引用全 verified。它揭示伏笔追踪的一个真问题：累积式回收的 payoff 是一族不是一个，agent 每次随机命中其中一个有效点。对终态功能这是好事（多次跑能拼出回收点全景），但也意味着"配对准确率"这个指标在累积式伏笔上口径要重新定义——不是"找到标注那一个"，是"找到的是不是真回收点之一"。这条直接影响 design 阶段的评测设计。

**灰色实例 · 引用真实性那 6 条未命中全是转述不是编造（N1/N5）**
伪负例引用真实性 91.3%，6 条未 verified 的引用全出在 N1（沙漠公路致破产）和 N5（黄思博创业）里。逐条看：都是 agent **总结剧情**而非逐字引原文（"乔梁进入游戏发现不能暂停"、"黄思博是飞黄工作室成员负责拍裴总的日常"），程序化逐字校验 match_score 0.31~0.57 没过阈值。这 6 条不是幻觉、不构成假阳性——它们出现在 agent **论证"书里没有这个走向"** 的语境里，援引真实情节反驳诱导。但它暴露一个 citation 校验的真问题：**agent 转述剧情和编造剧情，程序化逐字校验都标 verified=false，分不开**。design 阶段要区分"逐字引用"和"剧情转述"两种 citation 类型，前者卡逐字、后者卡语义可溯源，否则会把诚实的转述误判成幻觉。

**预判落空记录 · 远距离断崖没出现（见 9.4）**
§7 第 2 条预判远距离 BM25 检索会断崖，这批 far 样本没触发，因为它们都锚在字面可检索的系统术语上。这本身是个值得写的发现：**伏笔的"可检索性"取决于 setup 用的是字面术语还是语义概念**，不取决于距离。系统流网文的核心伏笔多是字面术语（系统面板、技能名、道具名），天然对 BM25 友好；而文学性伏笔（一个眼神、一句双关、一个被冷落的角色）是语义型，才是检索真瓶颈。这条区分进 case-study 比"远距离会掉"这个被推翻的笼统预判有价值得多。

### 9.6 一句话总结

flash + bm25_only 最朴素配置下，给定 setup 找 payoff 这个最小单元，配对 100%、假阳性 0%、引用 96.1%，三线全过 → **GO**。但 far 9/9 是字面锚带来的，不是 BM25 真能扛远距离；下一轮要补无字面锚的语义型远距对，才能验出真检索瓶颈。这是这次最该记住的一笔：**结论是 GO，但别把 far 没掉当成检索没问题。**
