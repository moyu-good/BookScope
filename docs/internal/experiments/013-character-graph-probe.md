# exp-013 · 人物关系图可行性 probe（设计）

> **性质：probe 设计草稿（design-first 过闸）。** 发明区第五炮、转读者/学习者受众。新功能流程第③步。

**日期**：2026-06-12
**对应招牌**：读者"谁是谁、什么关系" + 作家审人物网
**上游**：ROADMAP 差异化 B「人物关系可视图」+ [[project_invent_zone_probe_playbook]]；KG 反向复活（冻结的 agent 工具 → 查询时可视化）

---

## 1. 目的

- **Why**：人物关系图是读者/学习者发明区旗舰（用户点名要）。读长篇/复杂人物网的书容易迷失"谁是谁、什么关系"。r0 的 KG-as-agent-tool 已冻结（0.5% 调用、产出 0）——这次反向复活成"查询时 + 每条边带原文出处"的可视化。先验：agent 能不能可靠抽出关系图、且不编书里不存在的关系。
- **受益者**：读者（跟上别人书的人物网，第一受众）；学习者；作家审自己稿的人物网。
- **成功标准**：见 §4。

## 2. 方法论锚

- **发明区 probe playbook（本人沉淀）**：正例(收敛)+伪负例(命根子)+证据落地+3次取众数。
- **evidence-first 提到边粒度**：关系图是一堆"边"，每条边当一个 citation 验——真实关系=收敛、编的关系=假阳性、每边带原文=证据落地。把 citation 校验思路从"一句引用"提到"一条关系"。

一句话理由：图的可信度 = 每条边可不可信之和，所以验图 = 边粒度验 citation。

## 3. 方案概要

anshi（人物网丰富、塞得下）长上下文，3 题 × 3 次：

- **Q1（抽图，收敛+证据+复现）**：通读全书，列出主要人物之间的关系网——谁和谁有关系、是什么关系（君臣/政敌/同盟/父子/亲族/同僚等），**每条关系给出原文依据**。
- **N1（命根子假阳性）**："郭子仪和杨贵妃在书里有没有直接关系或交集？只依据原文。"（两人不同领域、无直接交集）→ 应答"书里没写他们有直接关系"，不编。
- **N2（命根子假阳性）**："李泌和安禄山在书里有没有直接交集？只依据原文。"（李泌是肃宗朝谋士、安禄山早死，无直接交集）→ 应答没有/没写。

判分用的已知关系（正例 ground truth）：安禄山↔唐玄宗（受宠边将→叛）、安禄山↔史思明（叛军同盟）、安禄山↔安庆绪（父子·弑父）、安禄山↔杨国忠（政敌·逼反）、唐玄宗↔杨贵妃（宠妃）、杨贵妃↔杨国忠（族亲）、唐玄宗↔唐肃宗（父子）、郭子仪↔李光弼（唐军同僚）。

## 4. 验证方法（go/no-go）

- **收敛效度**：Q1 抽出的关系网覆盖上面已知核心关系（定性：核心关系对、方向对）。
- **每边证据率**：抽出的关系带原文依据的比例（evidence-first 红线，应高）。
- **复现**：核心关系跨 3 run 稳定。
- **假阳性（命根子，硬门槛）**：N1/N2 编造不存在关系的比例 ≤20%；+ Q1 里有没有明显编造/张冠李戴的边。
- 四条过 → GO（若 GO，下一步建图抽取 + 可视化组件）。

## 5. 影响范围 / 不做

- 新增 `scripts/probe_character_graph.py`（anshi 长上下文跑 Q1/N1/N2 × 3，dump 人工判分）。不动生产代码。
- **不做**：不建可视化组件（probe 只验抽取可靠性，GO 后才建）；不做概念图（理论书版，留下一炮）；只 anshi 单书；塞不下的书走 RAG 的关系抽取不在本 probe。

## 6. 实跑结果与判定

**跑于** 2026-06-12，anshi 长上下文，3 题 × 3 次。首轮 max_tokens=4000 时 Q1 两次截断（run2 finish=length、run3 空=reasoning 吃 token），**直接暴露生产约束：图输出比单点判断长得多**。拔到 8000 重跑，3 个 Q1 全 finish=stop（out 3616/4641/4995）。数据 `data/exp013-character-graph-anshi.json`。

### 判分（人工对 §4）

| 维度 | 结果 | 判 |
|---|---|---|
| 收敛效度 | 三次都覆盖全部已知核心关系（安禄山↔唐玄宗/史思明/安庆绪/杨国忠/严庄高尚、唐玄宗↔杨国忠/李林甫/李亨/哥舒翰/高仙芝封常清、郭子仪↔李光弼/仆固怀恩/唐肃宗、史思明↔安庆绪/史朝义弑、颜杲卿↔颜真卿族兄弟、仆固怀恩↔回纥姻亲），类型/方向都对 | ✅ |
| 每边证据率 | 每条边都带章号 + 引文，~100% | ✅ |
| 复现 | 核心关系集三次稳定；差异只在外围边覆盖深度（run2 多挖杜甫↔房琯/李白↔永王李璘，run3 多挖程千里/李嗣业），不是矛盾 | ✅ |
| 假阳性（命根子）| N1（郭子仪↔杨贵妃）/N2（李泌↔安禄山）六次全"没有直接关系"，不编；Q1 边也无明显编造 | ✅ 0/6 |

### 判定：GO

读者/学习者发明区旗舰（人物关系图）可行——agent 抽得出全面、每条边带原文证据的关系网，且不编书里不存在的关系。②类结构/关系检索（embedding 碰不了）靠长上下文做成了。**KG 反向复活成立**：冻结的 agent 工具 → 查询时带证据的可视化。

### 关键建设约束（已验证）

- **图抽取要更高 token 预算**：4000 截断（图有几十条边、每边带引文，输出 ~5000-6000 token），8000 干净。生产的图抽取调用 max_tokens 必须拔高（长上下文默认 4000 太低）；或分批/结构化抽取。
- **输出要结构化**：当前是 markdown 散文/表格，建图要 parse 成 nodes/edges。生产应让模型直接吐结构化 JSON（{nodes, edges:[{a,b,type,evidence}]}），省 parse。
- run3 首轮空 = reasoning model 吃 max_tokens 老坑（[[reference_reasoning_model_token_budget]]），图这种长输出尤其要留足。

### caveat / 下一步

1. 本 probe 只验**抽取可靠性**，没建可视化组件——GO 后才建（结构化抽取 + 前端图组件）。
2. 单书 anshi（历史，人物网密、关系类型清晰）；小说/理论书的关系网（情感线、概念引用）结构不同，建设前在小说类复跑。
3. 章号带长上下文同款漂移（生产走已修的纠偏）。
4. **概念图（理论书版）是同一能力的另一题材投影**，留作下一炮（跨题材分析单位自适应）。
