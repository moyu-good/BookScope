## 1. 背景与动机

第 33 轮之前，团队把 MiniMax-M2.7 在《明朝那些事儿》上的高得分归因于"训练污染"——模型可能见过本书全文，靠记忆绕开 tool 调用。这是 exp-002 的核心假设。

但当时的 probe 题目设计有一个隐患：**问的都是常识题**，比如"这本书的主要角色有哪几个""洪武年间发生了什么"。这类题百度、维基百科、抖音科普文章都能答，不能证明模型真读过原文。

第 33 轮的 probe 是第一次尝试用"非常识性"的细节题来区分两种情况。

---

## 2. 核心问题

**训练集记忆 vs 背景知识**，如何区分？

- **背景知识**：任何接触过明史普及材料的人（或模型）都知道的信息——年号、人物关系、历史大事件。这类信息在维基、百科、历史教材里大量存在，LLM 从任何角度都能答。
- **训练集记忆**：只有真读过原文才能答的信息——作者在某页的具体措辞、某段对话的原文顺序、某个章节的叙事细节，这类信息在二手资料中极少出现。

probe 的核心设计原则由此产生：**常识题不算证据，局部文本信息题才算证据**。

---

## 3. 实验设计

### 3.1 两本书对比

| 书目 | 代号 | 预期训练数据熟悉度 |
|------|------|-----------------|
| 《明朝那些事儿》 | mingchao | 高（热门历史普及书，全网大量二次创作） |
| 《安史之乱》（薛宗正著） | anshi | 低（学术专著，网络流传少） |

anshi 的选择逻辑：出版印量小、网络评论极少、非普及读物，minimax M2.7 训练数据中包含全文的概率低。

### 3.2 题型设计

本次 probe 不用五道作家诊断题，而是专门问**出版信息 / 作者信息**：

- 这本书的作者是谁？
- 出版年份 / 出版社是什么？
- 这本书的主要内容是什么（需要读过才能准确描述的细节）？

之所以问出版信息，是因为：
- 如果模型真见过原文，出版信息应该很确定
- 如果模型只有"大致知道这本书存在"的背景知识，出版信息会模糊甚至出错
- anshi 这类冷门书，背景知识和训练记忆之间的差距最明显

### 3.3 关键测试

向 minimax 直接询问 anshi（《安史之乱》）的作者信息，故意不提供任何书本内容，看模型是否能正确回答。

---

## 4. 核心发现

### 4.1 anshi 作者信息错误——训练数据不熟悉的直接证据

minimax 对《安史之乱》（薛宗正著）的作者回答偏差明显：

- 模型把 anshi 的作者说成了**郝毅博等编者**而非薛宗正
- 或混淆成其他同名书目的作者（安史之乱有多个不同作者的版本，模型未能区分）
- 这说明模型没有见过薛宗正这本书的完整文本——只有"这个主题下有些相关书"的模糊背景知识

这是 anshi 训练数据不熟悉的**直接证据**：不是间接推理，是模型直接答错了核心出版信息。

### 4.2 mingchao 常识题的反面教训

同样的测试在 mingchao 上效果相反——模型能正确答出主要角色、年号、历史大事，但这恰恰说明**这些题型没有区分能力**：

- 任何接触过明史普及材料的人都知道朱元璋的年号是洪武
- 这些知识从史书、教材、Wikipedia 都能获取，不需要读过当明朝那些事儿原文

作者锤的正是这一点：**常识题的答对率证明不了什么**。

### 4.3 结论翻转：价值 reframe

原本的论断是"minimax 在 mingchao 上有训练污染 bug"。第 33 轮被锤后，结论翻转为：

**训练数据熟悉度差异是所有 LLM 的常态，不是某家特有的 bug。**

任何 LLM 都正常训练，对热门公开书熟悉、对冷门专著不熟悉，这是正常现象而非漏洞。BookScope 的价值主张因此从"针对 minimax 的训练污染问题"转向"对任何 LLM、任何文本都强制 evidence-from-text"——这才是普遍适用的方法论。

---

## 5. 衍生设计规则

### 5.1 probe 题型规则（写入 memory）

**禁止"常识题"作为训练污染证据**：维基/百科/抖音科普能答出的题，不算原文记忆的证据。

合格的 probe 题型需满足：
1. 答案只能从原文中获取（不在任何二手资料里）
2. 具体到章节内的事件顺序、对话措辞、细节描写
3. 两本书同一题型，在"熟悉书"和"冷门书"上答对率应有显著差距

### 5.2 prompt 设计规则（未实施，作为后续建议）

在 system prompt 或用户提示中加入说明："本书信息可能不在训练数据中，请严格基于用户提供的文本内容作答，不要依赖可能的训练记忆。"

这条规则的效果尚未实验验证，列为后续 probe 设计的候选方向。

### 5.3 常识题在 BookScope 场景中的标注

在 test-book-templates.md 的题目设计中，常识题（如"主要角色有哪几个"）应标注为：

```
[警告：通识题，不适用于训练污染 probe；
 适用于：功能验收 / 基础答题能力验证]
```

## 7. 后续实验方向

**exp-003 不是终点**，它产出的是一套"如何设计可信 probe"的方法论。后续 probe 实验应当：

1. 用**局部文本信息题**（具体对话、章节内顺序）取代常识题
2. 对 mingchao 和 anshi 用同一套 probe 题，比较答对率差距
3. 跑 ≥ 3 次取 std，避免单次 baseline 当 ground truth（见 memory `feedback_baseline_variance_first.md`）
4. 结果不要归因到"某家 LLM 的问题"，而是归因到"训练数据熟悉度"这个变量

本实验到此结束。它的价值是一次**方法论校正**，而非数据产出——把团队的 probe 设计从"凭直觉选题"拉到"有区分度的题型设计"。
