## 不变的做法：溯源解决，不修个案（作者反复强调）

作者举的**个例只是某一类问题的一个表述**，不是"只解决这一个"。任何问题都往根上刨——"这本书 / 这个 provider / 这次"只是症状，要的是这一类的**通用根治**。

- 例：人物图缺五虎将 → 不是给三国补名单，是整本功能"单次摘要（截 30 条）→ 穷尽抽取"的结构根因（见 1.4）。
- 例：综合引用没盖「鉴」→ 不是改这一条，是 verify 标记没透出的通用 bug。

写出来的东西反复在说"这本书 / 这次"——停下，拉到通用层重做。详见 memory `feedback_global_not_single_case`。

## 现在的判断（从项目定位倒推）

要实现"读整本书、只凭原文证据答长文本创作者/读者的硬问题"，拆三层，下层撑上层：

1. **地基**：检索捞得到对的原文 + 证据可信 + 跑得便宜。没这层，上面全是沙上建塔。
2. **差异化**：没人做过的深读能力——**按三类用户分别想**：作家（审自己稿找毛病）/ 读者（读懂别人书别剧透）/ 学习者（拿书学东西学手艺）。这是 BookScope 存在的理由。
3. **产品化 + 交付**：让真用户用得顺手 + 案例研究沉淀。

**2026-06-12 的转折**：伏笔追踪可行性 probe 判定 **GO**（找对 100% / 假阳性 0% / 引用 96% 真实）。第一次硬证据证明整个赌注成立——agent 真能做带证据的深读诊断、不瞎编。**下一程主轴：把发明区能力一个个做成真功能，地基按需拉起来撑它们。**

### 跨功能底座 · evidence-first 空语义 + 分量研判（溯源，非单一垂直）

| 根（class）| 是什么 | 触发实例 + 同根还波及 | 验收标准 |
|---|---|---|---|
| **"空"没有语义分级**（待核当万能兜底）| evidence-first 遇到抽不到 / 查不到默认落"待核"，但"空"有三种意思天差地别：① **确证为无 / 不适用**(=笃定答案，常是用户最想知道的) ② **真没抽到**(才该待核) ③ **信号性缺失**(1.7 已做对：owner 空=未派人、承诺判不出=未知)。① 和 ② 混成一个"待核"，把笃定的"无"显示得像系统故障。根=系统没建模"**确证缺失本身是答案**(negative finding)"。 | **触发**：公文密级(公开件本就无密级→该显"公开 / 无密级"非待核)、签发人(意见类常无)、紧急(未标=平件)。**同根波及**：关系图(没这条边 vs 没抽到)、伏笔(已断=答案 vs 没找到)、设定一致性(自洽=结论 vs 没扫到)、实体回溯(全书没出现 vs 搜漏)。**1.7 反而做对了**(loose_end / 未知)，照它回填。 | "空"做成共享三分语义(确证无 / 不确定 / 信号缺失)，各 evidence-first 功能统一遵守；公文头要素第一个回填；跨 ≥3 类功能(公文头要素 / 关系图 / 一致性)验证不再把"确证无"误显待核 |
