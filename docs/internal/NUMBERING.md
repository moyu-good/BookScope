# BookScope 编号速查（给作者的一页纸）

**起因**：2026-06-10 作者问"设计和各种编号到底是个啥？看不懂"。项目长出了七套编号各管一摊，从没写过总览。本页是人话版，新编号系统出现时必须同步更新本页。

---

## 七套编号

### r0 / r1 / r2 —— 架构代际（最大的版本概念）

产品怎么造的"大代"。**r0**：老路线，上传书先全量批量分析再静态展示（已冻结归档 `legacy/v7/`）。**r1**：现路线，你提问的那一刻 AI 才去查书、带原文证据回答（2026-04-20 起）。**r2**：r1 的内部通信协议换血（Anthropic 形态 → OpenAI 形态，ADR-007，2026-05-15），用户看不出区别，分支名仍叫 `r1-agent-loop`。

代际升级必须有 ADR + 作者签字。

### Sprint 0-11 —— 工期表

`docs/internal/ROADMAP.md` 的两周工期块，排到 2026-09-30 开源发布。开头的"时间线实况表"看哪些完成了哪些在跑。注意：实际完成顺序和编号顺序早就不一致了（Sprint 8 比 Sprint 3 先做完），看实况表别看编号。

### WP0-WP8 —— 工作包（临时编号）

2026-06-10 设计缺口评审（`docs/internal/design/2026-06-10-design-gap-review.md`）查出 13 个设计毛病，打包成 9 个工作包逐个修。每个 WP 一份设计稿在 `docs/internal/design/WP*.md`，状态写在文件头。全修完这套编号就归档，不会长期存在。

### exp-001 ~ exp-00N —— 实验编号

`docs/internal/experiments/` 下每个编号回答一个问题：001 基线对比（已改 exp-001b 待跑）/ 002 训练污染可证伪检验 / 003 训练污染 probe / 004 跨题材稳定性 / 005 r1 vs r2 / 006 KG 缓存 / 007 上下文头检索提升。实验文档含设计 + 实跑数据 + 判定；数据 JSON 在 `data/` 子目录按 `expNNN-` 前缀归档。

### ADR-001 ~ ADR-00N —— 架构决策记录（作者的控制点）

`docs/architecture-decisions/`。每个重大技术决策一份文件：背景 → 候选方案 → 推荐 → **作者签字才生效**。这是作者对项目方向的正式控制手段——AI 可以起草和推荐，签字权在人。

### v1 ~ v3.6 —— prompt 版本

`bookscope/agent/prompts/` 下给 AI 的指令书改版号。规矩：旧版本永不修改不删除（留作对照实验）；生产用哪版由 `loop_shared.py` 的 `CURRENT_PROMPT_VERSION` 常量决定，且每次运行记录进数据（WP0 之后）。reviewer 评分卡（rubric）同理独立编版本。

### 第 N 轮 / 第 N 波 —— 工作日志批次

`docs/internal/STATE.md` 的工作阶段号。"轮"是早期叫法（约前 35 轮），"波"是近期叫法，本质一样：一个连续工作 session 算一波，波内可以分段。纯日志用途。
