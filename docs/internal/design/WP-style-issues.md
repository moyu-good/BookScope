# WP-style-issues · 文体级毛病检测（功能队列第 3 个，design-first）

> 设计稿，作者已批"开发全部功能"。流程：本稿 → probe（GO 才建）→ build → live → 记一笔。

**目的**：帮作家审自己的稿——扫出文体级毛病：① 用词重复（某词/短语成了口头禅）、② 视角越界（限知视角里写了视角人物不可能知道的内心/事）、③ 支线失踪（埋了的支线/人物后文没交代）。每条钉原文。
**受益者**：作家（审稿找毛病）。
**成功标准**：扫出的毛病每条带原文、可核验；**命根子=不 cry wolf（不把正常文字编成毛病、不编不存在的问题）**——会乱报的审稿工具比没有更糟（让作家改本来没错的地方）。

**方法论锚**：① 整本书结构化功能模式；② 发明区 probe playbook（命根子=假阳性，这是本功能最重风险）。三类毛病有主观性，GO 同 pacing/一致性 软一档——验"不乱报 + 报的有原文"，不号称"抓全所有毛病"。

**方案概要**：
1. 端点 `POST /api/agent/style-issues`（一键）。
2. 长上下文整本进 system → 出结构化 JSON：`{issues: [{type: 'repetition'|'pov'|'dropped_thread', what: 问题描述, snippet: 原文片段, chapter}]}`。
3. **保守**：prompt 要求只报清楚的毛病、宁缺毋滥；每条 snippet 过 verify_citations，**核验不过的丢**（同一致性扫描的双守卫精神：编的毛病滤掉）。三守卫照焊。

**数据结构**：`{type, what, snippet, chapter, verified}`；前端按 type 分组（用词重复 / 视角越界 / 支线失踪）。

**前端**：左栏「文体体检」mode → 一键"扫文体毛病"→ 按类分组列出，每条朱批问题 + 原文为证 + 钤印。复用 SealMark + 评点卡。

**复用**：新建 `style_issues.py`（照搬 consistency_scan.py——找问题 + 原文核验才留 + 保守 prompt）+ 端点 + `StyleIssues.tsx` + App 左栏。

**probe（建前先跑）**：anshi（已出版、编辑过，理论上毛病少——正好测 cry wolf）。
- 正例（保守性）：扫 anshi，报的毛病数不爆炸 + 每条 snippet 原文核验过（≥90%）。well-edited 书报一堆 = cry wolf。
- **命根子伪负例**：要它确认一个**不存在**的文体毛病——如"『量子』这个词在书里是不是反复出现成了口头禅？"（安史之乱书里没"量子"）→ 应答"没有/没这个词"，**不编**。假阳性 ≤20% 硬门槛。

**不做**：不做自动改写建议（只指出 + 给原文，改不改作家定）；不做精确"抓全"承诺（辅助、非全覆盖）；大书塞不下先 422。

**验证**：probe 过 → 建 → live 抽查（anshi 不爆报 + 不存在的毛病不编）+ 单测零回归 + 前端 build。

## probe 结果（2026-06-16）：**GO**

- 正例（保守性）：anshi（已编辑出版）平均只报 **0.3 条/次**——不 cry wolf；报的原文核验 100%。
- 命根子假阳性 **0/6**：要它确认不存在的毛病（外书词"反复出现"、现代人物"贯穿全书"）3 次全判 false、不编。
