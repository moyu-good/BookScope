# WP-recap · 无剧透情节回顾（功能队列第 4 个，design-first）

> 设计稿，作者已批"开发全部功能"。流程：本稿 → probe（GO 才建）→ build → live → 记一笔。

**目的**：读长书隔几天回来忘了前情——给"我读到第 X 章"，回顾到此为止的关键人物/事件/线索，**绝不剧透后文**。
**受益者**：读者（追更/慢读，回来需要前情提要，又怕被剧透）。
**成功标准**：给出读到第 X 章为止的前情要点，每条钉原文；**命根子=零剧透（不提第 X 章之后的任何事）**。

**方法论锚**：① 整本书结构化功能模式；② **结构性保证胜过 prompt 哀求**——无剧透不靠"请别剧透"，靠**根本不把后文喂进上下文**：只截取第 1..X 章进 context，模型物理上看不到后文，编都没法编。这是本功能的设计核心，比其他功能的"prompt 约束"更硬。

**方案概要**：
1. 端点 `POST /api/agent/recap`，入参 `book_session_id` + `up_to_chapter`(X) + provider/key/...。
2. **只把第 1..X 章的原文拼进 system**（按 chunk 的真章号过滤 1≤chapter≤X；章号未知=0 的不放，宁缺毋滥保不漏后文）→ 长上下文回顾。
3. 出结构化 JSON：`{points: [{order, point: 前情要点, chapter, snippet}]}`，按时序。每条 snippet 过 verify_citations（**对照的也只是 ≤X 的 evidence**——后文片段自然核验不过被丢）+ 章号纠偏。三守卫照焊。

**数据结构**：`{order, point, chapter, snippet, verified}`，全部 chapter ≤ X。

**前端**：左栏「前情回顾」mode → 章节数字输入（读到第几章）+ "回顾"→ 竖向前情要点 + 钤印。复用时间线竖向样式 + SealMark。

**复用**：新建 `recap.py`（结构同 timeline，但 full_text 换成"≤X 章拼接" + evidence 也只 ≤X）+ 端点 + `Recap.tsx`（带章节输入，形态近 EntityRecall）+ App 左栏。

**probe（建前先跑）**：anshi，X = 中部章。
- 正例：≤X 的前情要点，引用真实性 ≥90%，**所有 cited chapter ≤ X**（无后文泄漏）。
- **命根子零剧透**：① 结构保证——只喂 ≤X，后文片段核验不过自动丢；② 再问"后面/结局怎样？"看它是否老实说"读到第 X 章、后文还没"，不编结局。

**不做**：不做"模糊章节边界"的智能截断（就按 chunk 真章号硬截，章号 0 的不放）；大书塞不下（≤X 部分仍超长）先 422；第一版不做"渐进解锁"动画等花活。

**验证**：probe 过（引用真实性 + 零后文泄漏）→ 建 → live 抽查（anshi 读到第 X 章回顾不提后文）+ 单测零回归 + 前端 build。
