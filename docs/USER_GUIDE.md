# BookScope 用户手册

> 面向首次接触 BookScope 的人：长篇作者、深度读者、研究者、学习者。
> 你已经看过 [README](../README.md)，知道 BookScope 是什么、为什么不直接用 ChatGPT。
> 这份手册告诉你：怎么实际用——既包括「问书」自由问答，也包括左栏 12 个整本书结构化功能。
>
> 命令和章节路径以仓库为准；模型名、接口地址以各厂商最新公布为准。

---

## 1. 三分钟开始用

### 1.1 装环境

```bash
git clone https://github.com/moyu-good/BookScope.git
cd BookScope
pip install -e ".[dev]"
python -m textblob.download_corpora    # 一次性 NLTK 资源
```

需要 Python 3.14+。如果 `pip install` 卡在编译包，多半是系统没装 C 编译器，按提示装一下即可。

### 1.2 起后端

```bash
uvicorn bookscope.api.app:create_app --factory --reload --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 就行。这一步不依赖任何 LLM key——只是把 API 起起来。

### 1.3 起前端

另开一个终端：

```bash
cd web
npm install
npm run dev
```

vite 默认开在 `http://localhost:5173`。开发模式下前端会把 `/api/*` 请求代理到 `http://localhost:8000`。

### 1.4 浏览器开起来

打开 `http://localhost:5173`。点左下角的设置图标，打开「设置 · LLM 配置」面板，跟着填：

1. **厂商**：默认 `DeepSeek（最便宜）`。下拉里有 8 家预设（DeepSeek / 智谱 GLM / 通义千问 / Kimi / Anthropic / OpenAI / Gemini / Grok）；选了非默认厂商会自动填好它的官方接口地址。详见 §3
2. **API Key**：把你的 BYOK key 粘进去（key 怎么拿见 §3）
3. **模型**：每家一个下拉，列了该厂商的官方模型 + 「自定义」。DeepSeek 默认 `deepseek-v4-flash`（最便宜大众档），留空即用它
4. **Base URL**：选了厂商会自动填；走代理 / 私有部署时可改；Anthropic 自动隐藏（后端不需要）

这些信息只在浏览器本地会话存，刷新页面即失效，不上传后端。

### 1.5 上传第一本书

仓库根有一本 `test*.epub`（《明朝那些事儿》第一卷），可以直接上传试。三阶段进度条会跑：

1. **解析** —— 读 epub 文件、抽章节
2. **切分** —— 按章节做 book-aware chunking
3. **KG 抽取** —— LLM 抽人物 / 章节范围等轻量索引

通常 30 秒到 2 分钟，看书的长度。中途黑屏不要急——日志在后端终端里。

### 1.6 问第一个问题

上传完成后，下方多出一个输入框。你可以：

- 点示例题按钮起步
- 自己写一道题，比如：`朱元璋早年经历过哪几次大事件？`

回车提交。你会看到 streaming 进度依次推：

- `iteration_start` —— agent 开始第 N 轮
- `tool_use` —— agent 决定调哪个工具（`search_chunks` / `get_chapter_range` / `list_characters_in_chapter`）
- `tool_result` —— 工具返回了什么
- `final_answer` —— 答案 + citation

首字一般在 5 秒内出现。整道题 30 秒到 4 分钟不等，取决于题型和 provider 速度。

## 2. 支持的文件格式

来自 `bookscope/ingest/loader.py`，当前实际支持：

| 格式 | 状态 | 说明 |
|------|------|------|
| `.epub` | 主力 | 推荐格式。章节结构清晰，切分质量最好 |
| `.txt` | 可用 | UTF-8 / latin-1 / cp1252 自动识别。章节靠启发式切，效果看文件本身的章节标记 |
| `.pdf` | 可用 | PyMuPDF 抽文本。扫描版 PDF 不行——要先 OCR |
| URL | 可用 | 单页 HTML，trafilatura 抽正文 |

大体积建议：500 KB 到 5 MB 的 epub 是甜蜜点。10 MB 以上的书要等 KG 抽取较久。

不支持的：mobi / azw3 / doc / docx——先转 epub 再上传。

## 3. 怎么选 LLM provider

BookScope 一律 BYOK——key 自己控制，项目里没有内置任何厂商 key。设置面板预置了 8 家主流厂商，选了厂商就自动填好它的官方接口地址和模型下拉：

| 厂商 | 怎么接 | 默认 / 代表模型 | 去哪拿 key |
|------|--------|----------------|-----------|
| **DeepSeek**（默认） | 原生 | `deepseek-v4-flash`（最便宜大众档） | platform.deepseek.com |
| 智谱 GLM | OpenAI 兼容 | `glm-4.6` / `glm-4-flash` | open.bigmodel.cn |
| 阿里 通义千问 | OpenAI 兼容 | `qwen-max` / `qwen-turbo` | dashscope（阿里云） |
| 月之暗面 Kimi | OpenAI 兼容 | `kimi-k2` / `moonshot-v1-128k` | platform.moonshot.cn |
| Anthropic Claude | 原生 | `claude-sonnet-4-6` | console.anthropic.com |
| OpenAI | OpenAI 兼容 | `gpt-4o` / `gpt-4o-mini` | platform.openai.com |
| Google Gemini | OpenAI 兼容 | `gemini-2.5-pro` / `gemini-2.5-flash` | aistudio.google.com |
| xAI Grok | OpenAI 兼容 | `grok-4` / `grok-3` | console.x.ai |

### 3.1 怎么挑

- **第一次用 / 写中文长篇** → DeepSeek，便宜、国内可直连、稳
- **英文论文 / 哲学经典 / 要长上下文** → Anthropic 或 Gemini
- **已经有某家的 key** → 直接选那家，模型下拉选一个或填「自定义」

### 3.2 关于模型名

每家下拉里的模型名是参考值，**以厂商官方最新公布为准**——拿不准就选「自定义」自己填准。后端只有两个 adapter：Anthropic 走原生，其余全走 OpenAI 兼容协议（换厂商 = 换 base_url + 换模型名），所以任何 OpenAI 兼容的服务（含自建代理、OpenRouter 等）都能用：选 DeepSeek 然后把 Base URL 改成你的端点即可。

### 3.3 key 试了不通？

看 §8 常见问题排查——多半是 key 失效、base_url 填错、或该厂商在你网络环境下要绕路。

## 4. 怎么问问题

### 4.1 BookScope 怎么路由你的问题

后台有个题型路由器（`bookscope/agent/fast_path.py`）。它先扫题面关键词决定走哪条路：

| 路径 | 何时触发 | 延迟典型值 | 适合什么题 |
|------|---------|-----------|-----------|
| `fast_general` | 题面短 + 含"几个 / 哪些 / 主要角色 / 哪个朝代"等 | 3-12 秒 | 通识列举题 |
| `fast_review` | 含"讲了什么 / 主题是 / 作者想表达" | 5-15 秒 | 要观点不要复述 |
| `fast_summary` | 含"概括 / 梗概 / 故事情节" | 5-15 秒 | 全书梗概 |
| `fast_rating` | 含"怎么样 / 值得读吗 / 好看吗" | 5-15 秒 | 评分判断 |
| `agent_loop` | 题面长 / 含诊断词（分析 / 评估 / 铺垫 / 节奏 / 伏笔 / 转变 / 漂移） | 30-240 秒 | 诊断诊查题 |

诊断词命中就一律走完整 agent loop——多轮 tool 调度才能给真判断。

### 4.2 四类好问题示范

**通识题**（fast_general）：

- `主要角色有哪几个`
- `故事发生在什么朝代`
- `全书共多少章`

**评论题**（fast_review）：

- `这本书在写什么`
- `作者想表达的核心是什么`

**摘要题**（fast_summary）：

- `用三段话概括全书故事`

**诊断题**（agent_loop，作家最该问的）：

- `朱元璋的性格转变是渐变还是突然硬扳的`
- `第 5 到第 10 章的铺垫是否连贯`
- `支线 X 的伏笔回收到位吗`
- `主角动机在第几章发生关键转变`

### 4.3 不好的问题

避免太开放、跨整本概括类的诊断题。这种题 agent 跑 12 轮也未必收敛，最后多半 `MaxIterationsExceeded`。

- ✗ `这本书写得好不好` —— 太开放，拆成"节奏 / 人物 / 伏笔"分别问
- ✗ `主角是个什么样的人` —— 拆成"主角在第 X 章的关键决定说明他是什么样的人"
- ✗ `所有人物关系怎样` —— 拆到具体两人 / 具体章节

### 4.4 怎么写好诊断题

三条原则：

1. **限定章节范围**：`第 5-10 章` 比 `全书` 准
2. **单一维度**：一次问"铺垫"或"节奏"，别一次问 5 个维度
3. **要判断不要复述**：`是否连贯` / `渐变还是硬扳` / `到位还是不到位`

## 5. 怎么读答案

### 5.1 答案主文

agent 给的答复通常 2-4 段。每个主张后面挂引用编号，对应下方 citation 列表。

### 5.2 citation 段

每条 citation 包含：

- `chapter`：章节号（来自 ingest 切分阶段标记）
- `snippet`：原文片段，原样不改写
- `verified` / `match_score`：系统已把这条引用跟原文比对过（3-gram 匹配）——LLM 编造的引用会在这里现形

如果一条主张没挂 citation，prompt 规则要求 agent 自己补——但 LLM 偶有漏。看到漏 citation 的关键判断，自己心里打个折扣，或者把问题改具体重新问一次。

### 5.3 怎么判断一条答案靠不靠谱

BookScope 内部有个评分 agent 在帮开发者打磨答案质量，但它的分数不展示给你——同一个 AI 给自己打分会偏高，分数对你没参考价值。你判断答案好不好，自己扫两眼就够，看这两点：

1. **关键结论后面有没有指回原文的引用？** 没引用的判断打个折——BookScope 立身之本就是结论要有原文证据，下方 citation 列表就是给你核对用的。
2. **它有没有给你下一步能用的判断，还是只在复述情节？** 一条答案如果只复述"发生了什么"，对深读 / 写作帮不上忙；真有用的是"这条线断了""这里铺垫薄了"这种你能接着改的判断。

这两条正好是答案最该有的两样东西：证据撑得住、读完知道下一步。用自己的眼睛看，不会被虚高的自评分误导。

## 6. 左栏的 12 个整本书功能

「问书」之外，左栏还有 12 个一键(或填一个词)就跑的整本书结构化功能。共同套路：

> **选好书 → 点左栏功能 → 看运行过程 → 得到结构化结果 + 用量统计。** 每条结论的原文出处都过核验，核验过的盖一枚朱砂「鉴」印(下称**钤印**)；核验不过的直接丢——宁可少说，不编。

按怎么用分三组：

### 6.1 一键就跑的(选好书直接点)

| 功能 | 点了得到什么 |
|------|-------------|
| **关系图** | 人物 / 概念关系网。可拖动节点、连线越粗 = 关系越亲密，点任意一条边看支撑它的原文。先选「人物关系图」或「概念关系图」 |
| **时间线** | 全书事件按真实时序排成竖线，多线 / 倒叙也还原；点一条看原文出处 |
| **节奏曲线** | 逐章张力柱状图，矮 = 松(拖沓)、高 = 紧(高潮)；点一根看这章依据 |
| **一致性**（设定一致性扫描） | 列出前后矛盾，每条两处对照原文；扫完没矛盾会正面告诉你「设定挺自洽」 |
| **论点结构** | 拆非虚构书的论证骨架，按论证推进列主张 + 原文为证 |
| **写作手法** | 列作者显著的写作手法 + 原文例子 |
| **知识卡片** | 出知识点卡，每张配一道苏格拉底自测题，点「翻看」展开解释 + 原文 |
| **文体体检** | 扫用词重复 / 视角越界 / 支线失踪，按类分组 |

### 6.2 要先输一个词的(回溯类)

| 功能 | 输什么 | 得到什么 |
|------|--------|---------|
| **实体回溯** | 一个人 / 物 / 地点 | 它在全书每次出现 + 在做什么 + 在哪章，竖线排列 |
| **概念演进** | 一个概念 | 它在全书怎么一步步发展，按章节先后排 |
| **母题追踪** | 一个主题 / 意象 | 它在全书的每次复现 |

> 回溯类有个诚实约定：**书里没有这个实体 / 概念 / 母题，就明确告诉你「没找到」，不硬凑。** 这是 evidence-first 的应有之义。

### 6.3 防剧透的(前情回顾)

**前情回顾**：告诉它你读到第几章，它**只把这一章之前的原文喂给模型**(后文物理上看不到)，回顾到此为止的前情。零剧透不是靠 prompt 哀求，是结构保证。追更、读到一半放下又捡起来时好用。

### 6.4 运行过程怎么看

点任意功能后，过去要黑盒等 40-90 秒。现在会显示：

- **运行时**：一条流水线(取全书 → 喂模型通读 → 梳理结构 → 核验原文)+ 进度扫光 + 实时计时器。不伪造百分比——一次长调用看不到中间态，只诚实显示跑了多久。
- **跑完**：一行小字告诉你这次**通读了多少字、花了多少 token(输入 / 输出)、用了多久**。命中缓存会显示「0 token」(因为没花钱)。

### 6.5 钤印是什么

结论旁的朱砂「鉴」小印 = **这条原文出处经程序跟全书原文逐字比对、命中了**。盖了印的引用可信；没盖印的(模型给了出处但没在原文里命中)说明可能是编的，自己留个心眼。这是 BookScope「证据优先」的视觉语言，不是装饰。

## 7. 多书管理

### 7.1 当前书与切换

左栏顶部「案上」显示当前正在读的书。点左下角「书库」打开书架，点任意一本切换；当前选中的会高亮。

### 7.2 历史问答按书隔离

每本书的「问书」问答记录存在浏览器本地，按 `book_session_id` 隔离。切书时当前输入框自动清空、历史列表换成新书的，不串台。

### 7.3 删书

书架里每本书带删除入口，点一下不会立刻删——会变成二次确认，再点才真删。删书会同时删后端 session + 本地历史。删了就回不来——再用要重新上传。

## 8. 常见问题排查

### 8.1 上传失败

| 现象 | 多半原因 | 怎么办 |
|------|---------|--------|
| `EmptyTextError` | epub 里没正文 / 全是图片 | 换一本，或先 OCR |
| 卡在解析 / 切分不动 | 文件太大 | 看后端终端日志；或换小一点的书 |
| 上传按钮点了没反应 | API key 没填 / 填错 | 点左下角设置图标，重填 key |

### 8.2 问完答案空 / 报错

前端 ErrorBanner 会显示人话提示，对应五类常见情况：

- **ContentFiltered（内容审核）** —— provider 拒答了。BookScope 已自动换 3 种说法重试。按提示换措辞再问，或换 provider。
- **RateLimited（限流）** —— provider 忙不过来。已自动退避重试 3 次。按倒计时等 60 秒再点重试，或去厂商后台看 key 调用次数上限。
- **ContextLimitExceeded（上下文超长）** —— 这本书 + 对话历史超过 provider 上限了。点新建对话开个新 session。
- **MaxIterationsExceeded（agent 没收敛）** —— 跑了 12 轮还没收敛。多半题问得太宽，按 §4.4 拆细。失败前已经查到的原文证据（partial_evidence）会一起带回来，不至于白等一场。
- **ProviderUnavailable（连不上）** —— 多半是 key 失效或网络。先去设置检查 key，再试网络。

错误兜底文案完整版见 `docs/UX_ERROR_COPYWRITING.md`。

### 8.3 答案不满意怎么办

按 §5.3 自己扫一眼觉得答得不够好（没引用 / 只在复述），可以：

1. 题目改具体：限定章节、拆维度（§4.4）后重新问一次
2. 换 provider 试——同一道题不同 provider 表现差别大
3. 如果是通识题，它本来就只复述事实、不给结构性判断，这是正常的，别太当回事

### 8.4 性能慢

| 阶段 | 典型耗时 | 怎么看 |
|------|---------|--------|
| 首次上传 KG 抽取 | 30 秒到 3 分钟 | 一次性。书越长越久 |
| 重开已索引的书 | 0.1 秒级 | 四层缓存（ADR-008）直接命中 |
| 通识题（fast_path） | 3-15 秒 | 正常 |
| 诊断题（agent_loop） | 30 秒到 4 分钟 | 正常但偏久。缓存层已落地，剩余耗时在 LLM 推理本身 |
| 首字延迟 | < 5 秒 | streaming 进度推送保证有反馈 |

诊断题目前就是这个速度。要快，把题问得更具体——agent 少走几轮就快了。

### 8.5 "为什么 ChatGPT 能答，BookScope 答不了"

这是设计选择，不是缺陷。

ChatGPT 直通能答的多半是它训练数据里见过的书——它在调用记忆，不是在读你给的文本。这套对名著有效，对你自己的草稿、新出的论文、冷门理论书都失效。

BookScope 不靠记忆，靠每次现场查原文。所以：

- **训练数据外的书** —— BookScope 准，ChatGPT 编
- **训练数据内的名著** —— ChatGPT 看着说得头头是道，但你没办法验它说的是不是原文里真有的；BookScope 慢一点但每条都能指回章节

如果你要的是"快速听个大概"，ChatGPT 更顺手。如果你要的是"基于原文的精读 / 草稿审阅"，BookScope 才是工具。

## 9. BYOK 与隐私

### 9.1 你的 API key

- 只存在你浏览器本地会话里，随每次请求带上，不在后端持久化
- BookScope 项目代码里没有任何内置 key
- 你可以随时去厂商后台 revoke

### 9.2 你上传的书

- 解析后的章节 + chunk + 索引存在后端进程内存（看 `bookscope/store/`）
- 当前版本是内存态 session——后端进程重启就没了
- 不上传到任何第三方
- 删书会清光

### 9.3 LLM 请求

agent 跑的时候，问题 + 检索到的原文片段会发给你选的 provider。所以：

- 用 deepseek / anthropic 时，你的原文片段会经过这家厂商
- 各家政策不一样，敏感内容（未发表草稿 / 私密笔记 / 涉密论文）请按你信任的厂商选
- BookScope 不在中间做日志留存

### 9.4 我能 self-host 吗

完全可以。BookScope 全部在你本地跑，没有任何外发的 telemetry。整个项目就是 `git clone` + `pip install` + `npm install` + 起两个本地服务，没有 phone home。
